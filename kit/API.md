## core.js

> Kit core: the foundation every other kit file and every game builds on.
>
> Owns:  the `Kit` global and game registry, `Kit.math` (scalar helpers, easing, unseeded random),
>        number / time formatting, the event bus, the object pool, the game clock (timers and
>        tweens that run on game time) and the per-game persistent store.
> Does not own: anything that touches the DOM, THREE or the frame loop (see shell.js), seeded
>        randomness (Kit.rng in loot.js) or progression models (model.js).
>
> Pure enough to run in node: the only browser global it reads is `localStorage`, and it copes
> when that is missing or blocked. Unit-tested by tools/test-kit.js.

### `Kit.math.TAU`

One full turn in radians.

### `Kit.math.clamp(value, min = 0, max = 1)`

Limits a value to a range.

- `value` *number*
- `[min=0]` *number*
- `[max=1]` *number*

**Returns** *number* `value`, or the nearer bound when it lies outside [min, max].

### `Kit.math.wrap(value, size)`

Wraps a value into [0, size), also for negatives (the `%` operator alone keeps the sign).

- `value` *number*
- `size` *number* - length of the cycle (must not be 0)

**Returns** *number*

```js
wrap(-1, 4) // 3
```

### `Kit.math.lerp(from, to, amount)`

Linear interpolation.

- `from` *number* - value at amount 0
- `to` *number* - value at amount 1
- `amount` *number* - 0..1 (not clamped, so it also extrapolates)

**Returns** *number*

### `Kit.math.damp(current, target, rate, dt)`

Frame-rate independent smoothing: moves `current` toward `target` by the same fraction per
second whatever the frame time, because the remaining distance decays as e^(-rate * dt).

- `current` *number*
- `target` *number*
- `rate` *number* - decay rate per second (about 5 is lazy, 20 is snappy)
- `dt` *number* - frame time in seconds

**Returns** *number* the new current value

```js
camera.position.x = damp(camera.position.x, player.x, 6, dt);
```

### `Kit.math.rand(minOrMax = 1, max)`

Uniform random number. `rand()` is 0..1, `rand(max)` is 0..max, `rand(min, max)` is min..max.

- `[minOrMax=1]` *number* - the upper bound when called with one argument, else the lower bound
- `[max]` *number* - exclusive upper bound

**Returns** *number*

### `Kit.math.randInt(min, max)`

Uniform random integer with both ends included.

- `min` *number*
- `max` *number*

**Returns** *number* integer in [min, max]

### `Kit.math.pick(items)`

Uniform random element of a list.

- `items` *T[]*

**Returns** *T* undefined when the list is empty

### `Kit.math.pickWeighted(rows, weightOf = (row) => row.weight || 1)`

Weighted random row, for spawn and loot tables. A row's chance is its weight over the total.

- `rows` *T[]*
- `[weightOf]` *function(T): number* - defaults to `row.weight`, or 1 when that is missing or 0

**Returns** *T* undefined when `rows` is empty

```js
pickWeighted(ENEMIES, (enemy) => enemy.weight)
```

### `Kit.math.shuffle(items)`

Shuffled copy of a list. The input is not changed.

- `items` *T[]*

**Returns** *T[]*

### `Kit.math.randomTools(random)`

Builds the list-randomising helpers over any source of random numbers, so the unseeded
Kit.math versions and the seeded Kit.rng versions (loot.js) share one implementation.

- `random` *function(): number* - returns a number in [0, 1)

**Returns** *RandomTools*

**Complexity** `pick` is O(1); `pickWeighted` is O(rows) time (two passes: total, then walk), O(1) space; `shuffle` is O(n) time and space

```js
const { shuffle } = Kit.math.randomTools(Kit.rng(42).next);
```

### `Kit.math.remap(value, inMin, inMax, outMin, outMax)`

Maps a value from one range onto another, clamped to the output range.

- `value` *number*
- `inMin` *number*
- `inMax` *number*

- `outMax` *number*

### `Kit.math.ease`

Easing functions: each maps progress 0..1 to eased progress, with f(0) = 0 and f(1) = 1.
The `out*` shapes start fast and settle; outBack, outBounce and outElastic overshoot or bounce.

### `Kit.math.sampleWeighted(rows, count, weightOf = (row) => (row.weight === undefined ? 1 : row.weight))`

Draws up to `count` different rows, each draw weighted: the "pick 3 of these, rarer ones less often" of offers and loot.
A row is never drawn twice, and rows whose weight is 0 or less are never drawn at all.

- `rows` *T[]* - the input is not changed
- `count` *number* - how many to draw; fewer come back when fewer rows have a positive weight
- `[weightOf]` *function(T): number* - defaults to `row.weight`, or 1 when that is missing

**Returns** *T[]* in draw order (heavier rows tend to come first)

```js
Kit.math.sampleWeighted(UPGRADES, 3, (row) => (row.rare ? 0.2 : 1))
```

### `Kit.math.rateLimiter(now)`

Makes a per-key rate limiter: `isReady(key, gap)` answers "has at least `gap` passed since this key last got a yes?"
and, when it says yes, starts that key's gap again. Sounds, toasts and hit sparks use it to stay readable in a crowd.

- `now` *function(): number* - the clock, in any unit (seconds of game time, performance.now() milliseconds)

**Returns** *function(string, number): boolean* `gap` is in the clock's unit; a gap of 0 or less always passes

```js
const isReady = Kit.math.rateLimiter(() => world.seconds);
if (isReady('hit', 0.05)) sfx.play('hit');
```

### `Kit.pool(create, onGet, onRelease)`

Creates an object pool, so things spawned repeatedly (bullets, particles, pickups) are reused
instead of allocated and garbage-collected.

- `create` *function(): \** - builds a new object when none is free
- `[onGet]` *function(\*, ...\*): void* - prepares an object for use; without it THREE objects are made visible
- `[onRelease]` *function(\*): void* - retires an object; without it THREE objects are hidden

**Returns** *Pool*

**Complexity** `get` and `release` are O(1); `each` and `clear` are O(live) time and space (they copy the live set so objects may be released during the pass). Memory is the high-water mark of live objects.

```js
const bullets = Kit.pool(() => make.sphere(0.1, 0xffee88), (bullet, origin) => bullet.position.copy(origin));
const bullet = bullets.get(player.position); bullets.release(bullet);
```

### `Kit.slotRing(capacity)`

Hands out the slots of a fixed-size buffer in a circle and remembers the stretch that may still
be in use, so a per-frame pass visits only that stretch instead of the whole buffer. Made for
short-lived things stored in pre-allocated arrays or instanced meshes (particles, trails, decals).

- `capacity` *number* - number of slots (a positive whole number)

**Returns** *SlotRing*

**Complexity** `claim` is O(1); `forEach` is O(span); `trim` is O(slots released). The window runs from the oldest unfinished slot to the newest, so a pass costs what is in use, not the capacity. O(1) space.

```js
const ring = Kit.slotRing(900);
const slot = ring.claim();                         // on spawn: write the particle into particles[slot]
ring.forEach((slot) => advance(particles[slot]));  // every frame
ring.trim((slot) => particles[slot].life <= 0);    // then let the window shrink
```

### `Kit.clock()`

Creates a game clock: timers and tweens that advance only when `update` is called, so pause,
hitstop and slow motion freeze or stretch them along with the game.

**Returns** *Clock*

**Complexity** scheduling is O(1); `update` is O(jobs) time per frame and allocates one array of the surviving jobs

```js
clock.after(2, spawnBoss);
const stop = clock.every(0.5, spawnGrunt);
await clock.tween(mesh.scale, { x: 1.4, y: 0.7 }, 0.12, 'outBack'); // target can be any object with numeric fields
```

### `Kit.isDevelopment()`

Is this page running for a developer (as opposed to the published page a player opens)? Development-time
warnings and checks only run when it is, so they cost a player nothing.
Set `window.KIT_DEV = true` or `false` before the kit loads to force the answer either way.

**Returns** *boolean* the forced value, else whether the page is served from this machine

```js
if (Kit.isDevelopment()) installExpensiveChecks();
```

### `Kit.warnings`

The development warnings raised so far, oldest first. Tools read this (`node tools/dev.js play` prints it).

### `Kit.warn(message)`

Tells the developer about a likely mistake that would otherwise only show up as odd behaviour. Each distinct
message is reported once, as a console warning, and only in development (see Kit.isDevelopment).

- `message` *string* - names the cause and the fix

**Returns** *boolean* true when the warning was reported, false when it was a repeat or the page is published

```js
Kit.warn(`runner: 4 stats in the top row; three fit a phone. Move one into ui.progress.`);
```

### `Kit.expectType(where, value, expected, example)`

Development check of one argument: warns (Kit.warn) when its type is obviously wrong. A kit function calls
this at its entry so the mistake is named where it was made, not three frames later.

- `where` *string* - the call as the developer wrote it, e.g. 'ui.stat(label)'
- `value` *\** - the argument received
- `expected` *string* - accepted type names separated by `|`: string, number, boolean, function, object, array, undefined (for an optional argument), null
- `example` *string* - a correct call, shown in the warning

**Returns** *boolean* whether the value has an accepted type

```js
Kit.expectType('ui.stat(label)', label, 'string', "ui.stat('Coins', 0)");
```

### `Kit.checkGame(definition, { games = Kit.games, skins = Kit.theme ? Object.keys(Kit.theme.SKINS) : null } = {})`

Checks a game definition before it is registered. Pure: it reports problems and changes nothing.

- `definition` *GameDefinition*
- `[known]` *Object* - what the definition is checked against
- `[known.games=Kit.games]` *GameDefinition[]* - the games already registered
- `[known.skins]` *?string[]* - valid `theme.skin` names; defaults to the skins of kit/theme.js when that is loaded, and null (skip the skin check) when it is not

**Returns** *{errors: string[], warnings: string[]}* each message names the cause and the fix; any error means the game cannot run

**Complexity** O(games) time for the duplicate-id scan, O(1) space

```js
Kit.checkGame({ id: 'orbit', create: 5 }).errors // ['`create` must be a function ...']
```

### `Kit.headlessOf(game)`

The headless handle of a game: its pure rules and data, for tests and tools that never open a page.

- `game` *GameDefinition \| string* - a definition, or the id of a registered game

**Returns** *?Object* the handle (`headless`, or the older `model` / `lab`), or null when the game has none

**Complexity** O(games) time when given an id (a scan of the registry), O(1) when given a definition

```js
const { progression } = Kit.headlessOf('miner');
```

### `Kit.register(definition)`

Registers a game with the menu. Each game file calls this once at load. The definition is checked first
(Kit.checkGame): a definition that cannot run throws here, at the mistake, instead of failing later.

- `definition` *GameDefinition*

**Returns** *number* how many games are now registered

```js
Kit.register({ id: 'orbit', name: 'Orbit', theme: { skin: 'neon' }, create: (ctx) => ({ update(dt, t) {} }) });
```

### Types

- **RandomTools**
  - `pick` *function(Array): \** - uniform random element (undefined for an empty list)
  - `pickWeighted` *function(Array, function(\*): number): \** - random row with chance weight / total weight
  - `shuffle` *function(Array): Array* - shuffled copy; the input is not changed
- **Bus**
  - `on` *function(string, function(\*): void): function(): boolean* - subscribe; returns an unsubscribe function
  - `emit` *function(string, \*=): void* - call every listener of the event with one payload
  - `clear` *function(): void* - drop every listener
- **Pool**
  - `live` *Set\<\*\>* - the objects currently handed out
  - `get` *function(...\*): \** - take an object (reused if one is free); extra arguments go to `onGet`
  - `release` *function(\*): void* - hand an object back; a no-op for objects that are not live
  - `each` *function(function(\*): void): void* - visit every live object (safe to release inside)
  - `clear` *function(): void* - release every live object
- **SlotRing**
  - `claim` *function(): number* - the next slot index, recycling the oldest slot once every slot has been used
  - `forEach` *function(function(number): void): void* - visit every slot in the live window, oldest first
  - `trim` *function(function(number): boolean): void* - shrink the window past the oldest slots that `isFree(slot)` reports as finished
  - `span` *number* - how many slots the live window covers (read-only)
- **Clock**
  - `after` *function(number, function(): void): function(): boolean* - run once after N game seconds; returns a cancel function
  - `every` *function(number, function(): void): function(): boolean* - run every N game seconds; returns a cancel function
  - `tween` *function(Object, Object\<string, number\>, number=, (string\|function(number): number)=): Promise\<void\>* - animate numeric properties of an object to target values; resolves when it finishes
  - `update` *function(number): void* - advance by `dt` game seconds (the shell calls this)
  - `clear` *function(): void* - drop every timer and tween
- **Store**
  - `get` *function(string, \*=): \** - the saved value, or the given default when the key was never set
  - `set` *function(string, \*): \** - save a JSON-serialisable value; returns it
- **GameInstance**
  - `update` *function(number, number): void* - called every frame with (dt, t) in game seconds
  - `[dispose]` *function(): void* - called when the game is left or restarted
  - `[debugState]` *function(): Object* - plain data describing the run right now (score, phase, positions); surfaced as `Kit.debug.state().state` to the developer overlay and to `node tools/dev.js play` predicates
- **GameDefinition**
  - `id` *string* - unique id; also the save namespace and the smoke-test name
  - `name` *string* - title on the menu
  - `tagline` *string* - one line under the title
  - `hook` *string* - the progression hook, shown on the menu card
  - `color` *number* - accent colour as a hex number
  - `order` *number* - menu position, ascending
  - `create` *function(Object): GameInstance* - builds the game from the shell's `ctx`
  - `[theme]` *Object* - the game's HUD theme (kit/theme.js); a game without one gets a development warning
  - `[headless]` *Object* - the game's pure rules and data, usable without THREE or the DOM (tests, tools). Add `headless.progression` (`createState`, `actions`, `apply`, `summary`; see tools/sim.js) and `make sim GAME=<id>` plays the game's long arc for simulated hours. Read it with Kit.headlessOf, which also accepts the older names `model` and `lab`

## model.js

> Kit model: progression as small, pure, composable pieces.
>
>   curve    - numbers from data:               Kit.curve.of({ base: 10, growth: 1.5 })(level)
>   table    - rows with unique ids:            Kit.table(ROWS).byId('gold')
>   stats    - base values + keyed modifiers:   stats.get('damage')
>   wallet   - currencies:                      wallet.spend(25)
>   upgrades - table x curve x stats x wallet:  upgrades.buy('pick')
>   goals    - progress from game events:       goals.track('catch', 1, fish)
>   persist  - the load / save / notify plumbing the stateful models share
>
> Owns:  the data models above. Each is useful alone; `upgrades` is only the composition of the others.
> Does not own: how they are drawn (ui.shop / ui.offer / ui.checklist in ui.js), random items
>        (loot.js) or where saves are stored (any `{ get(key, fallback), set(key, value) }`, usually ctx.save).
>
> No DOM, no THREE: runs in node and is unit-tested by tools/test-kit.js.

### `Kit.stats(base, { limits = {} } = {})`

Creates a stat block: base values plus modifiers keyed by where they come from, so applying a
source again replaces its earlier contribution instead of stacking on it.

- `base` *Object\<string, number\>* - stat name to base value
- `[options]` *Object*
- `[options.limits]` *Object\<string, [number, number]\>* - stat name to [min, max]; `get` never returns a value outside it however the modifiers stack (a crit chance stays in 0..1, a cooldown never reaches 0). Use -Infinity / Infinity for an open end. Stats without a limit are unbounded, as before.

**Returns** *{base: Object\<string, number\>, get: function(string): number, mod: function(string, ?ModSpec): void, preview: function(string, string, ?ModSpec): number, clear: function(): void, on: function(function(string=): void): function(): boolean}* `preview(statName, source, spec)` is what `get(statName)` would return if `source` contributed `spec` (null = nothing) instead of its current modifiers; nothing is changed and nobody is notified.

## meta.js

> Kit meta: progression that outlives a single run, and synergies between the things a player collects.
>
> Owns:  `Kit.profile` (lifetime statistics, permanent unlocks, achievements, account level, run history) and
>        `Kit.synergy` (set bonuses that switch on when a build holds enough items with the right tags).
> Does not own: per-run upgrades (`Kit.upgrades`), short goals (`Kit.goals`) or currencies (`Kit.wallet`) - it
>        composes with them. Pure: no DOM, no THREE; unit-tested in tools/test-kit.js.
>
> Depth comes from three timescales. Upgrades and goals cover the session; this module covers the long arc
> (what is different on run ten) and build identity (why two players' runs differ).

## flow.js

> Kit flow: how things change over time.
>
>   fsm        - states with enter / update / exit:    flow.go('fishing', { spot })

## lanes.js

> Kit lanes: "can a player get through this?" for anything laid out as rows of side-by-side lanes
> (endless runners, rhythm highways, falling-block dodgers, river crossings).
>
>   lanes.open       - which lanes of one row are free:         lanes.open(['wall', null, 'wall'], (cell) => cell === 'wall')  // [1]
>   lanes.reachable  - lanes of the last row a player can be in: lanes.reachable([[1], [0, 1], [0]])                            // [0]
>   lanes.isPassable - is there any way through every row:       lanes.isPassable([[0], [0, 2], [2]])                           // false
>
> Owns:  the reachability arithmetic only. A row is just the list of lane indices that are open in it.
> Does not own: what makes a lane open (the caller decides which obstacles block), timing, or anything visual.
>
> No DOM, no THREE: runs in node and is unit-tested by tools/test-kit.js.

### `Kit.lanes.open(cells, isBlocked)`

Lists the open lanes of one row of cells.

- `cells` *Array\<\*\>* - one entry per lane, left to right
- `isBlocked` *function(\*, number): boolean* - called with (cell, laneIndex); true when the lane cannot be passed

**Returns** *OpenLanes*

```js
Kit.lanes.open(['block', null, 'barrier'], (cell) => cell === 'block') // [1, 2]
```

### `Kit.lanes.reachable(rows, { reach = 1, from } = {})`

Walks the rows in order and returns the lanes of the last row the player can actually be standing in.
A lane counts only if it is open AND within `reach` of a lane that was reachable in the row before, so a row
whose only open lane is too far from where the player had to be makes everything after it unreachable.

- `rows` *OpenLanes[]* - first row first
- `[options]` *LaneOptions*

**Returns** *number[]* reachable lanes of the last row (empty when the rows cannot be passed, or when there are no rows and no `from`)

```js
Kit.lanes.reachable([[1], [0, 1, 2], [0, 2]], { reach: 1 }) // [0, 2]
```

### `Kit.lanes.isPassable(rows, options)`

True when at least one route leads through every row. Checking each neighbouring pair of rows on its own is not
enough: [[0], [0, 2], [2]] has a compatible lane in every pair but no single route, and this reports it as blocked.

- `rows` *OpenLanes[]* - first row first; no rows at all is trivially passable
- `[options]` *LaneOptions*

**Returns** *boolean*

```js
const isFair = Kit.lanes.isPassable(pattern.rows.map((row) => Kit.lanes.open(row.cells, (cell) => cell === 'wall')));
```

### Types

- **OpenLanes** - The open lanes of one row, as lane indices.
- **LaneOptions**
  - `[reach=1]` *number \| function(number): number* - how many lanes a player can shift between one row and the next: a constant, or a function of the index of the row being entered (so rows that are further apart can allow more)
  - `[from]` *number[]* - lanes the player may be in before the first row (default: any lane, so every open lane of the first row counts as reached)

## scrub.js

> Kit scrub: play a CSS animation on game time instead of wall-clock time.
>
> A CSS animation normally runs on the browser's clock, so it keeps going while the game is paused, frozen by hitstop
> or in slow motion. Kit.scrub pauses the animation and moves its playhead from a game-clock tween instead, so the

## hash.js

> Kit hash: a uniform spatial hash for "what is near this point?" among many moving things.
>
> Owns:  `Kit.spatialHash(cellSize)` - buckets of items by the square cell their centre falls in, rebuilt each frame.
> Does not own: what "near" means exactly (the caller tests the true distance of each candidate), the items
>        themselves, or fixed tile worlds (`Kit.grid` in kit/space.js). Pure: no DOM, no THREE; unit-tested in
>        tools/test-kit.js.
>
> Use it instead of comparing every pair: with n things spread over an area, all-pairs is O(n^2) per frame while
> insert-everything-then-query-each is O(n + n * k), k being the few things that share the queried cells.

### `Kit.spatialHash(cellSize)`

Makes a spatial hash over an unbounded plane.

- `cellSize` *number* - side of a cell in world units. Choose about the usual query diameter: much smaller and one query walks many cells, much larger and each cell holds many items.

**Returns** *SpatialHash*

**Complexity** clear O(buckets used), insert O(1), query O(cells touched + items in them); O(items + buckets) space. Nothing is allocated per frame once the buckets exist.

```js
const near = Kit.spatialHash(2);
near.clear();
enemies.forEach((enemy) => near.insert(enemy, enemy.x, enemy.z));
near.query(hero.x, hero.z, 3, (enemy) => { if (distance(enemy, hero) < 3) hit(enemy); });
```

### `Kit.beam.trace(grid, emitters, options = {})`

Follow light from its emitters across a grid until every ray is absorbed, leaves the board or repeats itself.
Cells whose kind has no optic are transparent, so targets may sit in the path of a ray.

- `grid` *object* - - a Kit.grid
- `emitters` *Beam[]* - - rays to start with (light begins in the cell after the emitter's own)
- `[options]` *object*
- `[options.optics]` *Object\<string, Optic\>* - - optic per cell kind; kinds not listed let light through
- `[options.kindOf]` *(cell: \*) =\> string* - - how to read a cell's kind (default `cell.kind`)
- `[options.lights]` *(cell: \*, color: \*) =\> boolean* - - does light of this colour light this cell? (default: nothing is a target)

**Returns** *{segments: BeamSegment[], lit: {x: number, y: number, color: \*, distance: number}[], passes: {x: number, y: number, color: \*, distance: number}[]}* `lit` lists each lit cell once, with the cells travelled from the emitter when light first reached it. `passes` lists every distinct (cell, colour) pair that lit a cell, for targets that need several colours at once.

**Complexity** O(cells x headings x colours) time and space: each (cell, heading, colour) ray is walked at most once, and a walk is at most max(width, height) cells. A 6 x 7 board with three colours traces in a few microseconds.

```js
const grid = Kit.grid.parse(['>./', '..*'], { '/': { kind: 'mirror', slant: 1 }, '*': { kind: 'target' } });

```

### `Kit.beam.reflect(dir, slant)`

Direction of light after bouncing off a diagonal mirror.

- `dir` *number* - - incoming DIRS4 index
- `slant` *number* - - 0 for a "/" mirror (rises to the east), 1 for a "\" mirror (falls to the east)

**Returns** *number* outgoing DIRS4 index

```js
Kit.beam.reflect(0, 0) // 3: light heading east leaves a "/" mirror heading north

With rows growing downward, "/" swaps east with north and south with west (0<->3, 1<->2, i.e. 3 - dir);
"\" swaps east with south and west with north (0<->1, 2<->3, i.e. flip the lowest bit).
```

### `Kit.search.shortest({ start, keyOf, movesOf, isGoal, limit = DEFAULT_SEARCH_LIMIT })`

Breadth-first search for the shortest list of moves that reaches a goal. Works for any puzzle whose states can be
given a string key: sliding blocks, light routing, sokoban, lights-out.

- `problem` *object*
- `problem.start` *\** - - the state to search from (treated as immutable)
- `problem.keyOf` *(state: \*) =\> string* - - equal states must give equal keys
- `problem.movesOf` *(state: \*) =\> {move: \*, state: \*}[]* - - every legal move from a state and the state it leads to
- `problem.isGoal` *(state: \*) =\> boolean*
- `[problem.limit]` *number* - - give up after exploring this many distinct states

**Returns** *{moves: \*[], explored: number} \| null* the moves in order (empty when `start` is already a goal), or null when no goal is reachable within the limit

**Complexity** O(states x moves per state) time, O(states) space, both capped by `limit`: breadth-first search visits every state closer than the goal. Keep `movesOf` tight (list only moves that can matter) before raising the limit.

```js
Kit.search.shortest({ start: 1, keyOf: String, isGoal: (n) => n === 10,
    movesOf: (n) => [{ move: '+1', state: n + 1 }, { move: 'x2', state: n * 2 }] }).moves // ['+1', 'x2', '+1', 'x2']
```

### `Kit.search.difficulty(solution)`

How hard a solved puzzle is, as one number: the moves a perfect player needs plus the base-2 logarithm of the states
a blind search had to look at (how much there is to consider). A one-tap tutorial rates about 2, a bed with a
dozen interacting pieces about 15.

- `solution` *{moves: \*[], explored: number}* - - a result of shortest()

**Returns** *number*

```js
Kit.search.difficulty({ moves: ['a', 'b', 'c'], explored: 64 }) // 9
```

### `Kit.search.generate({ propose, solve, accept = () => true, attempts = DEFAULT_GENERATE_ATTEMPTS })`

Generate-and-verify: propose puzzles until one is proven solvable and good enough. Nothing unverified ever comes back.

- `recipe` *object*
- `recipe.propose` *(attempt: number) =\> \** - - a candidate puzzle for this attempt (0, 1, 2, ...), or null to skip it
- `recipe.solve` *(puzzle: \*) =\> ({moves: \*[], explored: number} \| null)* - - usually a call to shortest()
- `[recipe.accept]` *(solution: object, puzzle: \*) =\> boolean* - - is this one good enough? Default: any puzzle that needs a move
- `[recipe.attempts]` *number*

**Returns** *{puzzle: \*, solution: object, attempt: number, isAccepted: boolean} \| null* the first accepted candidate; failing that the hardest one that needs at least one move (by difficulty()) with isAccepted false; null when every candidate was unsolvable or already solved

**Complexity** O(attempts x cost of solve). With shortest() as the solver that is attempts x its state limit at worst.


## crowd.js

> Kit crowd: many things moving through a Kit.grid world at once. Pure: no DOM, no THREE - runs in node (see tools/test-kit.js).
>
>   flow    - one breadth-first search from the goal cells; every walker then reads its next cell from the result
>   slide   - move a circle through the grid's world space, sliding along blocked cells
>   buckets - a uniform spatial hash: "who is near this point" without comparing every pair
>   views   - keep a set of pooled views in step with a list of plain entities (acquire new, release gone, place all)
>
> Each function's docstring has a runnable example and its cost.
>
> Owns: crowd pathing, circle-versus-cell collision, neighbour queries and entity-to-view bookkeeping.
> Does not own: the grid (kit/space.js), single-walker routes (grid.path, Kit.measure), steering feel (speeds, separation,
>               knockback: the game's), or what a view is (the acquire / release callbacks decide).

### `Kit.crowd.UNREACHABLE`

### `Kit.crowd.flow(grid, goals, isPassable, options = {})`

Builds a flow field: the step distance from every reachable cell to the nearest goal. One search serves any number of
walkers, so a crowd of fifty costs the same as a crowd of one. Rebuild it only when a goal changes cell.

- `grid` *Object* - a Kit.grid
- `goals` *CrowdCell[]* - cells walkers head for (goals outside the grid are ignored; a goal counts as open)
- `isPassable` *CrowdCellTest* - true for cells a walker may stand on
- `[options]` *{ diagonal?: boolean }* - diagonal: allow diagonal steps (default true)

**Returns** *FlowField*

**Complexity** build: O(cells) time and space, once per goal change. distanceAt: O(1). next: O(1) (at most 8 neighbours). A crowd of n walkers therefore costs O(cells + n) per goal change, against O(n x cells) for a search per walker.

```js
const field = Kit.crowd.flow(grid, [grid.fromWorld(hero.x, hero.z)], (cell) => !cell);
const step = field.next(zombieCell.x, zombieCell.y); // null means "walk straight at the goal" or "cut off"
```

### `Kit.crowd.buckets(bucketSize)`

A uniform spatial hash over the ground plane: entities are dropped into square buckets, and a neighbour query
reads only the buckets a circle touches. Use it wherever every entity must look at its neighbours (separation,
area damage, flocking): the all-pairs loop it replaces grows with the square of the crowd.

- `bucketSize` *number* - world units per bucket; pick about the largest query radius, so a query touches few buckets

**Returns** *{ fill: (entities: CrowdPoint[]) =\> void, near: (x: number, z: number, radius: number) =\> CrowdPoint[] }* fill: forget everything, then file each entity under its current position (call once per frame); near: every filed entity whose bucket touches the square around (x, z). It is a superset of the circle: the caller still checks the exact distance. Entities that moved since `fill` are found where they were.

**Complexity** fill: O(n) time, O(n) space. near: O(b + k) for b buckets touched and k entities in them, so a pass where each of n entities queries its neighbourhood is O(n) expected for evenly spread crowds, against O(n squared) for all pairs. Worst case (everyone in one bucket) degrades to O(n squared).

```js
const hash = Kit.crowd.buckets(1.5);
hash.fill(zombies);
hash.near(hero.x, hero.z, 3).filter((zombie) => Math.hypot(zombie.x - hero.x, zombie.z - hero.z) <= 3);
```

### `Kit.crowd.views(acquire, release)`

Keeps one view per entity: a simulation can stay plain data (arrays of `{ id, ... }`) while meshes, sprites or DOM nodes
come and go to match it.

- `acquire` *(entity: { id: \* }) =\> \** - makes or borrows the view for a new entity (for example pool.get)
- `release` *(view: \*) =\> void* - gives back the view of an entity that is gone (for example pool.release)

**Returns** *(entities: { id: \* }[], place: (view: \*, entity: \*) =\> void) =\> void* sync: call once per frame; `place` runs for every living entity after views were acquired and released

**Complexity** sync: O(entities + views) time per call; O(views) space.


## net.js

> Kit net: multiplayer as a shared key -> value state that every player sees, over any transport.
>
>   const net = Kit.net.session(transport, { validate });
>   net.set('token/t1', { x: 3, y: 4 });          // everyone converges on it (last writer wins, per key)
>   net.on('token/', (key, value, from) => ...);   // hear a key or a whole prefix, your own writes included
>   net.emit('roll', { total: 17 });               // a moment: delivered live, never stored
>   net.presence({ cursor: { x, y } });            // high-rate "me right now" state; net.onPeers(listener)
>
> Owns:  the session (state convergence, events, presence pass-through, the rate-limited outbox)
>        and Kit.net.loopback, the in-memory reference transport used by tests and same-page bots.
> Does not own: any real network. The session only talks to a Transport (typedef below); the hosted
>        page's room + database transport lives in net-claude.js and trust wrappers in net-trust.js.
>        Game code does not change when the transport does.
>
> Trust: every peer runs `validate(key, value, sender, previousEntry)` on what it hears and ignores
> what fails, so rules like "only the GM edits the map, players move only their own token" hold on
> every screen. The sender is stamped by the transport, never read from the message.
>
> No DOM: runs in node and is unit-tested by tools/test-kit.js.

### `Kit.net.session(transport, { validate, rate = DEFAULT_SEND_RATE } = {})`

Opens a session over a transport.

- `transport` *Transport*
- `[options]` *Object*
- `[options.validate]` *function(string, \*, Sender, Entry=): boolean* - run on every entry heard live; false ignores it. Gets (key, value or undefined for a delete, sender, the entry held before).
- `[options.rate=20]` *number* - outgoing messages per second

**Returns** *Object* `{ id, ready, get(key), has(key), keys(prefix), all(prefix), set(key, value), patch(key, fields), delete(key), on(keyOrPrefix, listener), emit(topic, data), onEvent(topic, listener), presence(patch), onPeers(listener), tick(dt), autoTick(ms), close() }`. `ready` resolves once the durable store (if any) has loaded.

**Complexity** `get` and `has` are O(1); `set`, `patch`, `delete` and `emit` are O(size of the value) for the size guard and serialising, plus O(listeners); `keys` and `all` are O(keys held). Memory is O(keys ever written): deleted keys leave a tombstone so the delete can win over an older set that arrives late.

```js
const net = Kit.net.session(hub.join('me'), { validate: (key, value, from) => !key.startsWith('map/') || from.by === 'gm' });
net.on('token/', (key, value, from) => moveToken(key, value));   // returns unsubscribe
net.set('token/me', { x: 3, y: 4 });
// every frame: net.tick(dt)   (or once: net.autoTick())
```

### `Kit.net.newer(candidate, current)`

The Lamport version rule that makes every peer converge: an entry replaces what is held when
its counter is higher, and when two peers wrote with the same counter (concurrent writes) the
higher peer id wins. Both comparisons are the same on every screen, so everyone picks the
same winner whatever order the messages arrive in.

- `candidate` *Version*
- `[current]` *Version* - the held version; anything is newer than nothing

**Returns** *boolean*

### Types

- **Version** - [Lamport counter, peer id] of the write that produced an entry.
- **Entry** - One key's state as stored and sent.
  - `[v]` *\** - the value (absent on a delete)
  - `ver` *Version*
  - `[del]` *1* - present when the key was deleted (a tombstone, so the delete can win over older sets)
- **Sender**
  - `peer` *string* - the sending peer's id
  - `[by]` *string* - who that peer acts for (a player name, 'gm'), when the transport knows
  - `[isMe]` *boolean* - true for this session's own messages
  - `[stored]` *boolean* - true when the entry came from the durable store rather than live
- **Message** - The wire protocol: a state write, a live event, or a newcomer asking for the current state.
- **DurableStore** - The optional durable path: late joiners load it and dropped live messages are healed by it.
  - `load` *function(): Promise\<Array\<[string, Entry]\>\>* - every stored entry
  - `save` *function(string, Entry): (Promise\<void\>\|void)* - store an entry (the store keeps the newer version)
  - `subscribe` *function(function(string, Entry): void): void* - hear entries as they are stored
- **Transport** - The fast path: low latency, may drop messages, replays nothing.
  - `id` *string* - this peer's id
  - `send` *function(Message): void* - deliver to every peer, this one included
  - `onMessage` *function(function(Message, Sender): void): void* - hear messages; the transport stamps the sender
  - `[maxBytes]` *number* - largest message it carries
  - `[presence]` *function(Object): void* - merge fields into this peer's presence
  - `[onPeers]` *function(function(Array): void): function(): void* - hear the roster; returns unsubscribe
  - `[close]` *function(): void*
  - `[store]` *DurableStore*

## net-trust.js

> Kit net trust: small decorators that make a Kit.net transport safer to listen to. Pure: no DOM, no network.
>
> Owns:  checks and wrappers that sit between a transport and Kit.net.session
>          Kit.net.isSaneEntry(entry)        - is this entry's version one an honest peer could have produced right now?
>          Kit.net.guarded(transport)        - a transport that silently drops "set" messages failing that check
>          Kit.net.withSender(transport, fn) - a transport whose senders carry extra, locally decided fields
>          Kit.net.checked(net, validate, self) - a session whose own writes are held to the same rule as everyone's
>          Kit.net.remember(hub, storage)    - keep a loopback hub's durable store in browser storage, so a table
>                                              played on one device survives a reload
> Does not own: the session, the rules of any game (those are the `validate` function a game gives the session), or any real network.
>
> Why versions need a check: a session orders writes by a counter and adopts the highest counter it hears. A peer that
> sends a huge counter would win its keys forever and drag everyone's counter towards the number range's end. Honest
> counters never exceed the current time in milliseconds by much (they start at zero and grow by one per write), so a
> horizon of "now plus a few minutes" rejects the attack without any clock synchronisation.

### Types

- **Entry** - what a session stores per key
  - `[v]` *\** - the value (absent for a deletion)
  - `[del]` *1* - present when the key was deleted
  - `ver` *[number, string]* - version: [counter, id of the peer that wrote it]

## net-claude.js

> Kit net-claude: a Kit.net transport for a page published as a claude.ai Artifact. No server of your own, nothing to configure.
>
> The few-lines way (hosted when the platform is there, a working single-player table when it is not):
>   const table = await Kit.net.open({ table: 'friday-game', validate });
>   table.net.set('score/' + table.me.by, 3);
>   table.net.on('score/', (key, value, from) => draw(key, value));
> The transport alone, when a game manages its own sessions:
>   const transport = await Kit.net.claude({ table: 'friday-game' });   // null when the page is not hosted there
>   const net = Kit.net.session(transport || localTransport, { validate, rate: transport ? transport.rate : undefined });
>
> Owns:  mapping the Kit.net transport contract onto the platform's `room`, `db` and `user` capabilities (reached only
>        through `await claude.use(name)`), the exact `capabilities` object the page must be published with
>        (Kit.net.claude.capabilities), and telling the game who the viewer is and what they may do.
> Does not own: game rules (the session's `validate`), conflict resolution (the session), or any UI.
>
> HOW IT IS WIRED
>   Fast path   one named room per table (room.join), two topics. Low latency, lossy, never replayed.
>                 kn.a  admin-only: the platform refuses it to anyone below Editor, so a message heard on it is proof
>                       that its sender is a game master. Senders get { admin: true }.
>                 kn.p  opened to "interact": what Contributors send. Senders get { admin: false }.
>               If named rooms are refused the lobby room is used instead and messages carry the table name.
>   Durable path  one db document per key, holding the entry and its version. Late joiners load it; dropped fast
>               messages are healed by it (onSnapshot). Where a document lives says who wrote it:
>                 kn-gm/<table>/k/<key>       writable by Editors and the owner only  -> sender { admin: true }
>                 kn-own/<userId>/<table>/<key>  writable by that user only ({self})   -> sender { by: userId }
>               Stored entries are delivered through the same path as live messages, so the session's `validate` runs
>               on them with a sender the platform vouches for. kn-own/<userId> itself is a small document listing
>               the tables that user has written to, which is how other players discover whose keys to read.
>   Identity    always from the platform's stamp ({ peer, by, isMe, sameTab, guest }) or from the document's location,
>               never from anything inside a message or a document.
>
> WHO IS WHO (share-menu level -> role here)
>   Owner, Editor   game master: user.canEdit() is true. Sends on kn.a and writes kn-gm, so every screen sees
>                   { admin: true } on what they do. Several Editors are co-GMs.
>   Contributor     player: sends on kn.p and writes only their own kn-own subtree. What a player may change is the
>                   game's `validate` (for example "move only a token you own"); the platform already guarantees which
>                   user a change came from.
>   Viewer, Commenter  spectator: receives everything live and reads the stored table, and may show a cursor (presence
>                   is open to everyone in the room), but every send and every write is refused by the platform. The
>                   transport notices the first refusal, reports role "viewer" and stops trying.
>   Signed out, or arrived by public link without being admitted: cannot join the room; sees the stored table if the
>                   platform lets them read it at all. The page still works as a single-player table.
>
> LIMITS (the platform's, surfaced as Kit.net.claude.LIMITS)
>   A message is at most 4 KiB of JSON. Emits and presence share about 40 messages a second per viewer, so the session
>   is asked to send at most 20 a second and presence is flushed at most 10 times a second. Fast messages may be dropped
>   and are never replayed. Everyone in the room receives everything: fog of war and hidden tokens are a courtesy of
>   honest clients, not secrecy. Up to 60 players' subtrees are followed per table (the 64-listener cap).

### Types

- **ConnectionState**
  - `table` *string*
  - `role` *'gm'\|'player'\|'viewer'*
  - `isLive` *boolean* - the room is joined (messages travel in real time)
  - `isConnected` *boolean* - the room reports a live connection right now
  - `isDurable` *boolean* - the document store is in use (the table survives everyone leaving)
  - `errorCode` *string\|null* - last platform error worth showing, if any
  - `droppedOversize` *number* - fast messages skipped for exceeding the size limit
- **OpenTable**
  - `net` *Object* - the Kit.net session: set / get / on / emit / presence, already ticking by itself. set / patch / delete return false (and do nothing) when `validate` refuses them.
  - `isHosted` *boolean* - true on the platform; false for the single-player fallback
  - `me` *{by: string\|null, name: string, isAdmin: function(): boolean}* - who this player is
  - `state` *function(): ConnectionState*
  - `onState` *function(function(ConnectionState): void): function(): void*
  - `close` *function(): void*

## dice.js

> Kit dice: dice notation in, a structured roll out. Pure: no DOM, no THREE, no hidden randomness (the caller passes the rng).
>
> Owns:  parsing notation into a plan, rolling a plan with a Kit.rng, the bounds of a plan, and a one-line text form of a result.
> Does not own: drawing dice, announcing rolls to other players (send the notation and the rng seed; every screen re-rolls it and
>               gets the same dice, so a total can never disagree with the dice shown), or any game system's meaning of a result.
>
> Notation (case is ignored; spaces are allowed around signs and around adv / dis):
>   2d6+3      two six-sided dice plus three          d20        one die (the count defaults to 1)
>   4d6kh3     keep the highest three                 2d20kl1    keep the lowest one
>   4d6dl1     drop the lowest one                    4d6dh1     drop the highest one
>   3d6!       exploding: a die showing its top face adds another die
>   d20 adv    advantage: roll two, keep the highest  d20 dis    disadvantage: roll two, keep the lowest
>   d%         a hundred-sided die                    4dF        fudge dice showing -1, 0 or +1

### `Kit.dice.parse(notation)`

Parse dice notation into a plan. Throws an Error naming the problem when the text is not valid notation or asks for too much.

- `notation` *string* - for example "2d6+3", "4d6kh3", "d20 adv + 2"

**Returns** *RollPlan*

**Complexity** O(length of the notation) time; O(terms) space, at most LIMITS.TERMS.

```js
Kit.dice.parse('d20 adv+2').text // "2d20kh1+2"
```

### `Kit.dice.roll(notationOrPlan, rng = Kit.rng())`

Roll a notation or a parsed plan. The same plan and the same rng seed always give the same result.

- `notationOrPlan` *string\|RollPlan*
- `[rng]` *{int: function(number, number): number}\|function(): number* - defaults to a fresh, randomly seeded Kit.rng

**Returns** *RollResult*

**Complexity** O(dice rolled) time and space, at most LIMITS.TERMS x (LIMITS.DICE_PER_TERM + LIMITS.EXPLOSIONS); a keep rule sorts one group, O(d log d).

```js
const roll = Kit.dice.roll('4d6kh3', Kit.rng(7));
roll.total; roll.dice.map((die) => die.value);
```

### `Kit.dice.range(notationOrPlan)`

The smallest and largest total a plan can produce, ignoring explosions.

- `notationOrPlan` *string\|RollPlan*

**Returns** *{min: number, max: number}*

**Complexity** O(terms) time, O(1) space.

### `Kit.dice.describe(result)`

One line of text for a result: every die in brackets, dropped dice in parentheses, then the total.

- `result` *RollResult*

**Returns** *string*

**Complexity** O(dice rolled) time and space.

```js
Kit.dice.describe(Kit.dice.roll('4d6kh3+2', Kit.rng(1))) // "4d6kh3+2: [6, 4, 3, (1)] + 2 = 15"
```

### `Kit.dice.check(modifier = 0, advantage = null)`

Notation for a d20 check with a modifier.

- `modifier` *number* - added to the die (negative subtracts)
- `[advantage=null]` *'adv'\|'dis'\|null* - roll two and keep the best or worst

**Returns** *string*

```js
Kit.dice.check(3, 'adv') // "2d20kh1+3"
```

### `Kit.dice.LIMITS`

Upper bounds on what a notation may ask for. Notation arrives from other players, so every size is capped:
a roll must stay cheap to compute and small enough to show.

### Types

- **Keep**
  - `highest` *boolean* - true keeps the highest dice, false the lowest
  - `count` *number* - how many dice are kept
- **DiceTerm** - one group of identical dice in a plan
  - `sign` *1\|-1* - whether the group adds to or subtracts from the total
  - `count` *number* - dice rolled before any explosion
  - `sides` *number* - faces per die (FUDGE_FACES.length for fudge dice)
  - `isFudge` *boolean* - faces are -1, 0, +1 instead of 1..sides
  - `explodes` *boolean* - a die on its top face adds another die
  - `keep` *Keep\|null* - which dice count toward the total; null keeps all
- **NumberTerm** - a flat modifier in a plan
  - `sign` *1\|-1*
  - `value` *number*
- **RollPlan** - a parsed notation
  - `text` *string* - canonical notation ("2d20kh1+3")
  - `terms` *Array\<DiceTerm\|NumberTerm\>*
- **Die** - one rolled die, for display
  - `value` *number* - the face showing
  - `sides` *number*
  - `isKept` *boolean* - false when a keep/drop rule discarded it
  - `isBonus` *boolean* - true when it was added by an explosion
- **RolledTerm**
  - `sign` *1\|-1*
  - `text` *string* - the term's own notation ("4d6kh3" or "3")
  - `dice` *Die[]* - every die rolled, in roll order (empty for a flat number)
  - `subtotal` *number* - signed contribution to the total
- **RollResult**
  - `text` *string* - canonical notation
  - `total` *number*
  - `terms` *RolledTerm[]*
  - `dice` *Die[]* - every die of every term, flattened for display
  - `natural` *number\|null* - the kept face of the first d20 group when exactly one of its dice is kept (a check), else null

## sight.js

> Kit sight: what can be seen from a cell, and how far apart cells are, on a Kit.grid. Pure: no DOM, no THREE.
>
> Owns:  Kit.sight   - field of view (fog of war) and line of sight between two cells
>        Kit.measure - grid distance rules for rulers, and cheapest routes through terrain for movement previews
> Does not own: what a cell is. Callers say which cells block sight, which can be walked and what they cost,
>               so the same functions serve walls, doors, smoke or deep water.

### `Kit.sight.fov(grid, originX, originY, { radius, blocks, into })`

Cells visible from one cell. Opaque cells are visible themselves (you see the wall, not past it).

- `grid` *Object* - a Kit.grid
- `originX` *number* - column of the eye
- `originY` *number* - row of the eye
- `options` *Object*
- `options.radius` *number* - how far the eye sees, in cells
- `options.blocks` *CellTest* - true for cells that stop sight
- `[options.into]` *Uint8Array* - an existing mask to add to, so several eyes share one mask

**Returns** *Uint8Array* mask of grid.w * grid.h entries, 1 = visible; index = y * grid.w + x

**Complexity** O(radius^2) time (each cell inside the radius is visited at most once per quadrant, independent of the board's size) and O(board cells) space for the mask, or none when `into` is passed. A radius of 8 is about 200 cell visits, so recomputing for every token on every move is far inside a frame.

```js
const mask = Kit.sight.fov(grid, 3, 4, { radius: 8, blocks: (cell) => cell === '#' });
if (mask[y * grid.w + x]) drawLit(x, y);
```

### `Kit.sight.los(grid, from, to, blocks)`

Is there a clear straight line between two cells? The end cells themselves never block (a token standing in a
doorway can be seen), only the cells strictly between them.

- `grid` *Object* - a Kit.grid
- `from` *{x: number, y: number}*
- `to` *{x: number, y: number}*
- `blocks` *CellTest*

**Returns** *boolean*

**Complexity** O(cells on the line) time and space.

### `Kit.sight.cellsBetween(from, to)`

The cells a straight line passes through, from one cell centre to another (Bresenham), both ends included.

- `from` *{x: number, y: number}*
- `to` *{x: number, y: number}*

**Returns** *Array\<{x: number, y: number}\>*

**Complexity** O(longer axis of the offset) time and space.

### `Kit.measure.RULES`

How many cells a move counts as, by rule id. Each takes the number of orthogonal and diagonal steps of the move.

### `Kit.measure.AREAS`

Area templates by id: which cells around a centre an effect of a given radius covers. Add a row to add a shape.

### `Kit.measure.between(from, to, ruleId = 'alternating')`

Distance in cells between two cells under a rule (a ruler from A to B).

- `from` *{x: number, y: number}*
- `to` *{x: number, y: number}*
- `[ruleId='alternating']` *string* - a key of Kit.measure.RULES

**Returns** *number* cells (may be fractional for 'euclidean')

```js
Kit.measure.between({ x: 0, y: 0 }, { x: 3, y: 4 }, 'alternating') // 5: three diagonals (4 cells) and one straight
```

### `Kit.measure.along(cells, ruleId = 'alternating', costOf = () => 1)`

Distance in cells along a path of adjacent cells (a walked route), under a rule. Diagonals are counted over the
whole path, so under 'alternating' the 5-10-5 rhythm carries across corners. `costOf` multiplies the step into a
cell (2 for difficult terrain).

- `cells` *Array\<{x: number, y: number}\>* - each next to the one before
- `[ruleId='alternating']` *string*
- `[costOf]` *function(number, number): number* - (x, y) -> multiplier for entering that cell; default 1

**Returns** *number* cells

**Complexity** O(path length) time, O(1) space.

### `Kit.measure.label(cells, { unitsPerCell = 5, unitName = 'ft' } = {})`

Text for a distance: cells converted to table units.

- `cells` *number*
- `[scale]` *{unitsPerCell?: number, unitName?: string}* - defaults to 5 ft per cell

**Returns** *string*

```js
Kit.measure.label(7) // "35 ft"
```

### `Kit.measure.route(grid, from, to, { passable, costOf = () => 1, maxCost = Infinity })`

Cheapest walk between two cells (Dijkstra over eight directions). A diagonal step is refused when either cell
beside it is impassable, so routes never cut through wall corners.

- `grid` *Object* - a Kit.grid
- `from` *{x: number, y: number}*
- `to` *{x: number, y: number}*
- `options` *Object*
- `options.passable` *CellTest* - true for cells that can be entered
- `[options.costOf]` *CellTest* - multiplier for entering a cell (2 for difficult terrain); default 1
- `[options.maxCost]` *number* - give up beyond this search cost (keeps previews cheap on big maps)

**Returns** *Array\<{x: number, y: number}\>\|null* cells from `from` to `to` inclusive, or null when there is no way

**Complexity** O(n log n) time and O(n) space, n = cells cheaper to reach than the destination (at most the board, or the disc that `maxCost` allows). A path preview on a 40 x 40 board is a few thousand heap operations.

### `Kit.measure.area(shapeId, centre, radius, ruleId = 'alternating')`

The cells an area template covers. Cells are not clipped to any board; filter with grid.inside if needed.

- `shapeId` *string* - a key of Kit.measure.AREAS
- `centre` *{x: number, y: number}* - cell the area is centred on
- `radius` *number* - in cells
- `[ruleId='alternating']` *string* - distance rule used by shapes that measure

**Returns** *Array\<{x: number, y: number}\>*

**Complexity** O(radius^2) time and space.

```js
Kit.measure.area('circle', { x: 5, y: 5 }, 2).length // 21 under 5-10-5
```

- **AreaShape**
  - `label` *string*

## tabletop.js

> Kit tabletop: the rules of a shared tabletop, as plain data over Kit.net keys. Pure: no DOM, no THREE, no network of its own.
>
> Owns:  the key scheme below, the shape of every shared value (and cleaning untrusted ones), who may change what
>        (the `validate` function for Kit.net.session), the board grid built from map rows, what a viewer can see
>        (fog of war), turn order, ink stroke packing, roll and ping announcements, and a starter scene.
> Does not own: drawing, input, sound, or which transport carries the keys (games/table.js and Kit.net do that).
>
> KEY SCHEME (every value is small JSON; "GM" = a sender the transport vouches for as admin)
>   stage                    { scene: <sceneId> }: the scene everyone is looking at            GM
>   scene/<sceneId>          Scene                                                              GM
>   map/<sceneId>/<row>      string, one terrain character per cell of that row (see TERRAIN)   GM
>   door/<sceneId>/<x>.<y>   1 while the door at that cell stands open (absent = closed)        GM, or a player with a token beside it
>   token/<id>               Token (it names the scene it stands in)   GM adds, removes and moves between scenes; its owner
>                            moves it and edits name, hp and conditions; any player may claim an unowned player character
>   sheet/<id>               Sheet for token <id>                      GM, or the token's owner
>   turn                     Turn                       GM; the owner of the token whose turn it is may end that turn
>   ink/<by>/<sceneId>/<stroke>.<part>   InkChunk       the player whose id is <by> (add or erase), or the GM
>   gm/<by>          1                          GM only: lets every screen label who the game masters are
> EVENTS (live moments, never stored; always cleaned before use)
>   roll   { notation, seed, label, tokenId }   everyone re-rolls the notation from the seed, so totals cannot disagree with dice
>   ping   { x, y }                             a pulse on the board, in cells
> PRESENCE (display only, never authority)
>   { name, color, scene: <sceneId they are looking at>, cursor: [x, y], drag: [tokenId, x, y] | null,
>     ruler: [x0, y0, x1, y1] | null, area: [shapeId, x, y, radius] | null }       board coordinates in cells
> A campaign is simply the set of keys: any durable transport store (the hosted database, or a loopback hub kept in
> browser storage with Kit.net.remember) persists and reloads it whole.

## input.js

> Kit input: one pointer abstraction for touch, mouse and keyboard.
>
> Owns:  turning raw pointer and key events on the stage canvas into three game-level events
>        (tap, swipe - once per gesture, drag - start / move / end), the live pointer state, the
>        virtual joystick (`stick`) and its on-screen ring, and pointer-to-world picking.
> Does not own: HUD buttons (ui.js handles its own clicks), game rules, or the listeners' lifetime
>        beyond `dispose()` (the shell calls that on exit / restart).
>
> Needs the DOM and THREE, so it is exercised by tools/smoke.js rather than unit tests; the
> gesture maths is kept in the small pure functions at the top.

### `Kit.input(ctx)`

Creates the input layer for a game. The shell does this and exposes it as `ctx.input`.

- `ctx` *Object* - the shell context (uses renderer, size, camera, paused)

**Returns** *{pointer: PointerState, stick: {x: number, y: number, active: boolean}, onTap: function(function(PointerEventInfo): void): function(): boolean, onSwipe: function(function('left'\|'right'\|'up'\|'down'): void): function(): boolean, onDrag: function(function(PointerEventInfo): void): function(): boolean, useStick: function(boolean=): void, ground: function(number=, number=, number=): ?THREE.Vector3, hit: function(THREE.Object3D[], number=, number=): (Object\|undefined), dispose: function(): void}* `stick.x / .y` are -1..1 in screen space (+x right, +y DOWN the screen), driven by a drag from the touch-down point or by WASD / arrows. Each `on*` returns an unsubscribe function.

  - `down` *boolean* - is a finger / button down?
  - `x` *number* - current position, CSS pixels from the left
  - `y` *number* - current position, CSS pixels from the top
  - `nx` *number* - x in normalised device coordinates, -1 (left) .. 1 (right)
  - `ny` *number* - y in normalised device coordinates, -1 (bottom) .. 1 (top)
  - `sx` *number* - where the current gesture started, pixels
  - `sy` *number* - where the current gesture started, pixels
  - `t0` *number* - when the current gesture started, `performance.now()` milliseconds
  - `id` *?number* - pointerId of the gesture (other fingers are ignored until it ends)
  - `swiped` *boolean* - has this gesture already fired its swipe?
  - `moved` *number* - farthest the gesture has strayed from its start, pixels
- **PointerEventInfo** - Payload of tap and drag events.
  - `phase` *'start'\|'move'\|'end'\|'tap'*
  - `x` *number* - position, pixels
  - `y` *number* - position, pixels
  - `nx` *number* - normalised device x, -1..1
  - `ny` *number* - normalised device y, -1..1 (up is positive)
  - `dx` *number* - movement since the previous event, pixels
  - `dy` *number* - movement since the previous event, pixels
  - `tx` *number* - total offset from the gesture's start, pixels
  - `ty` *number* - total offset from the gesture's start, pixels

## fx.js

> Kit fx: juice.
>
> Owns:  short-lived feedback effects - particle bursts (one instanced mesh), shockwave rings,
>        rectangular frame pulses, glow pops, camera shake, screen flash, floating text, hitstop
>        and slow motion.
> Does not own: the frame loop (shell.js calls `update`, `applyShake` and `undoShake`), sound
>        (sfx.js), post-processing such as bloom (post.js) or lasting scene objects (make.js).
>
> Needs the DOM and THREE, so it is exercised by tools/smoke.js rather than unit tests.

### `Kit.fx(ctx)`

Creates the effects layer for a game. The shell does this and exposes it as `ctx.fx`.

- `ctx` *Object* - the shell context (uses scene, camera, size, make, tween, after, timeScale)

**Returns** *Object* `{ burst(pos, options), ring(pos, options), pop(pos, options), frame(pos, options), shake(amount), flash(color, ms, strength), floater(text, pos, options), hitstop(ms), slowmo(scale, hold, recover) }` for games, plus `update(dt)`, `applyShake()`, `undoShake()` and `dispose()` for the shell.

```js
fx.burst(enemy.position, { count: 20, colors: [0xff5d73, 0xffc145], speed: 6 });
fx.ring(player.position, { color: 0x6ea8ff, size: 4 });
fx.shake(0.5); fx.hitstop(70); fx.floater('+5', coin.position, { color: '#ffc145' });
```

#### `Kit.fx().burst(pos, options = {})`

Throws out a burst of small cubes.

- `pos` *WorldPoint* - where they start
- `[options]` *BurstOptions*

**Complexity** O(count) time, O(1) space: particles are written into pre-allocated slots

#### `Kit.fx().ring(pos, options = {})`

Sends out an expanding, fading shockwave ring.

- `pos` *WorldPoint* - centre
- `[options]` *RingOptions*

#### `Kit.fx().pop(pos, o = {})`

A soft additive flash that swells and fades: the bloom-friendly "pop" of a kill, a pickup or a muzzle. Sprites are pooled,
and it runs on game time through ctx.tween, so pause and hitstop freeze it with everything else.

- `pos` *{ x: number, y: number, z: number }* - centre in world units
- `[o]` *{ color?: number, size?: number, life?: number, bright?: number, opacity?: number }* - color: 0xRRGGBB; size: final diameter in world units; life: seconds; bright > 1 blooms (default 1.5); opacity: starting alpha 0..1

```js
fx.pop(enemy.position, { color: 0xff5d73, size: 3 });
```

#### `Kit.fx().frame(pos, o = {})`

An expanding, fading rectangular outline lying flat: the square cousin of ring() for box-shaped things (slabs, tiles, cards).
It runs on game time through ctx.tween, so pause and hitstop freeze it with everything else.

- `pos` *{ x: number, y: number, z: number }* - centre in world units (drawn just above pos.y)
- `[o]` *{ width?: number, depth?: number, color?: number, grow?: number, life?: number, delay?: number, bright?: number, thickness?: number }* - width / depth: starting footprint in world units (depth defaults to width); grow: how much larger it ends, as a fraction (0.4 = +40%); life / delay: seconds; color: 0xRRGGBB; bright > 1 blooms; thickness: border as a fraction of the side (see make.frame)

```js
fx.frame(slabTop, { width: 4, depth: 3, color: 0x9fe8ff, bright: 2.4 });
```

#### `Kit.fx().shake(amount = 0.4)`

Shakes the camera. Calls do not stack: the strongest recent hit wins.

- `[amount=0.4]` *number* - 0..1

**Returns** *number* the trauma now

#### `Kit.fx().flash(color = '#fff', ms = 140, strength = 0.5)`

Flashes the whole screen and fades it out.

- `[color='#fff']` *string* - CSS colour
- `[ms=140]` *number* - fade time, milliseconds
- `[strength=0.5]` *number* - starting opacity, 0..1

#### `Kit.fx().floater(text, pos, options = {})`

Shows a short text that rises and fades ("+5", "MISS").

- `text` *string*
- `pos` *WorldPoint \| {x: number, y: number}* - world point, or screen pixels with `options.screen`
- `[options]` *FloaterOptions*

#### `Kit.fx().hitstop(ms = 60)`

Freezes the game for a moment (the shell skips game updates while `ctx._freeze` is positive).
Overlapping calls keep the longer freeze.

- `[ms=60]` *number* - milliseconds

**Returns** *number* the freeze now pending, seconds

#### `Kit.fx().slowmo(scale = 0.3, hold = 0.35, recover = 0.4)`

Drops game speed, holds it, then eases back to normal. Timed in real seconds.

- `[scale=0.3]` *number* - game speed while held (1 = normal)
- `[hold=0.35]` *number* - seconds at that speed
- `[recover=0.4]` *number* - seconds to ramp back to 1

#### `Kit.fx().update(dt)`

Advances every effect. The shell calls this once per frame with REAL seconds, so effects keep
playing through hitstop and slow motion.

- `dt` *number* - seconds

#### `Kit.fx().applyShake()`

Offsets the camera for this frame's render. The shell calls this just before rendering and
`undoShake` just after, so the shake never drifts the camera the game is steering.

#### `Kit.fx().undoShake()`

_Undocumented: add a JSDoc block in the source._

#### `Kit.fx().dispose()`

Clears floating text when the game is left (the scene's meshes are disposed by the shell).

### Types

- **WorldPoint** - A position in world units; a THREE.Vector3 fits.
- **BurstOptions**
  - `[count=12]` *number* - particles
  - `[color=0xffffff]` *number* - 0xRRGGBB for every particle
  - `[colors]` *number[]* - pick each particle's colour from this list instead
  - `[bright=1]` *number* - multiplies the colour; above 1 it passes the bloom threshold and glows
  - `[speed=4]` *number* - launch speed, world units / s (each particle gets 35-100% of it)
  - `[life=0.6]` *number* - seconds (each particle gets 60-120% of it)
  - `[size=0.14]` *number* - cube edge, world units (each particle gets 60-140% of it)
  - `[gravity]` *number* - fall acceleration, world units / s^2 (default 10, or 0 when flat)
  - `[up]` *number* - extra upward launch as a fraction of speed (default 0.6, or 0 when flat)
  - `[dir]` *[number, number, number]* - launch direction; particles fan out around it
  - `[spread=1]` *number* - how wide the fan around `dir` is (0 = a jet)
  - `[floor=-Infinity]` *number* - height particles bounce on
  - `[flat=false]` *boolean* - keep particles in the horizontal plane with no gravity (top-down 2D games)
- **RingOptions**
  - `[color=0xffffff]` *number* - 0xRRGGBB
  - `[size=2.5]` *number* - how much the radius grows, world units
  - `[life=0.35]` *number* - seconds
  - `[y]` *number* - height to draw at (default: just above pos.y)
  - `[width=0.18]` *number* - band thickness as a fraction of the radius (0.04 = a hairline)
  - `[bright=1]` *number* - above 1 pushes the colour past the bloom threshold
  - `[facing='ground']` *'ground'\|'camera'* - 'ground' lies flat; 'camera' stands the ring up to face ctx.camera, for side-on and 2D views where a flat ring is seen edge-on and vanishes
- **FloaterOptions**
  - `[screen]` *boolean* - `pos` is { x, y } in screen pixels instead of a world point
  - `[color]` *string* - CSS colour
  - `[size]` *number* - font size, pixels
  - `[gameTime]` *boolean* - play on the game clock (Kit.scrub), so it freezes with pause and hitstop and stretches in slow motion

## sfx.js

> Kit sfx: a tiny WebAudio synth. No audio assets.
>
> Owns:  the shared AudioContext (created lazily, unlocked on the first touch or key press, as
>        browsers require), two voices (`tone`, `noise`), the table of named sound presets,
>        the persisted mute switch and the haptic `buzz`.
> Does not own: music (music.js) or deciding when a sound plays (games call `Kit.sfx.play`).
>
> A singleton rather than a per-game factory: `Kit.sfx` is the same object as `ctx.sfx`.
> Needs WebAudio, so it is exercised by tools/smoke.js rather than unit tests.

### `Kit.sfx.tone({ freq = 440, to, dur = 0.1, type = 'triangle', vol = 0.3, delay = 0 } = {})`

Plays one oscillator note that fades out. Silent until the audio context has been unlocked.

- `[options]` *ToneOptions*

```js
Kit.sfx.tone({ freq: 660, to: 990, dur: 0.08, type: 'square', vol: 0.15 });
```

### `Kit.sfx.noise({ dur = 0.15, vol = 0.3, freq = 1200, q = 0.7, type = 'lowpass', delay = 0 } = {})`

Plays a burst of filtered white noise that fades out. Silent until the audio context has been unlocked.

- `[options]` *NoiseOptions*

```js
Kit.sfx.noise({ dur: 0.2, freq: 900, q: 1.5, type: 'bandpass' });
```

### `Kit.sfx.names`

Names accepted by play().

### `Kit.sfx.play(name, { pitch = 1, vol = 1, gap = 0 } = {})`

Plays a named preset.

- `name` *string* - one of `Kit.sfx.names`; unknown names are ignored
- `[options]` *Object*
- `[options.pitch=1]` *number* - frequency multiplier (1.06 is about a semitone up)
- `[options.vol=1]` *number* - volume multiplier
- `[options.gap=0]` *number* - seconds; skip this call if the same preset played less than `gap` ago, so a crowd of hits in one frame is one clean sound instead of a wall of noise (0 = no limit)

**Returns** *boolean* true when the sound was played

```js
Kit.sfx.play('coin', { pitch: 1 + combo * 0.05, gap: 0.04 });
```

### `Kit.sfx.setMuted(shouldMute)`

Switches all sound off or on, and remembers the choice.

- `shouldMute` *boolean*

### `Kit.sfx.buzz(milliseconds)`

Haptic tick on devices that support it (most Android phones; a silent no-op elsewhere, including iOS Safari).

- `milliseconds` *number* - Length of the buzz; keep ticks under ~20ms and big hits under ~50ms.

### Types

- **ToneOptions**
  - `[freq=440]` *number* - starting frequency, Hz
  - `[to]` *number* - frequency to sweep to over the duration, Hz (omit for a steady pitch)
  - `[dur=0.1]` *number* - seconds
  - `[type='triangle']` *'sine'\|'square'\|'sawtooth'\|'triangle'* - oscillator shape
  - `[vol=0.3]` *number* - starting gain, 0..1
  - `[delay=0]` *number* - seconds from now until it starts
- **NoiseOptions**
  - `[dur=0.15]` *number* - seconds
  - `[vol=0.3]` *number* - starting gain, 0..1
  - `[freq=1200]` *number* - filter frequency, Hz (low = thump, high = hiss)
  - `[q=0.7]` *number* - filter resonance
  - `[type='lowpass']` *'lowpass'\|'highpass'\|'bandpass'* - filter type
  - `[delay=0]` *number* - seconds from now until it starts
- **Voice** - One layer of a preset: ToneOptions or NoiseOptions plus how to play it.
  - `play` *function(Object): void* - the voice function (`tone` or `noise`)
  - `pitched` *string[]* - which frequency fields are multiplied by play()'s `pitch`

## make.js

> Kit make: scene-building helpers.
>
> Owns:  colour conversion, cached materials, shape meshes, instanced crowds, canvas textures,
>        groups, the ground plane, the sky / fog / lights "stage", glow sprites, outline frames,
>        scrolling dot fields and per-frame batches.
> Does not own: animation (ctx.tween, fx.js), game rules, post-processing (post.js), pixel-art
>        sprites (pixel.js) or disposal (the shell disposes the whole scene on exit / restart).
>
> Every mesh helper adds what it builds to the scene (or to `options.parent`) and returns it.
> Colours: the renderer outputs sRGB, so every hex colour is converted to linear space here.
> Build materials through this module, or convert with `make.color(hex)`; a raw
> `new THREE.Color(hex)` looks washed out.
>
> Needs the DOM and THREE, so it is exercised by tools/smoke.js rather than unit tests.

### `Kit.make(ctx)`

Creates the scene-building helpers for a game. The shell does this and exposes them as `ctx.make`.

- `ctx` *Object* - the shell context (uses scene)

**Returns** *Object* `{ color, mat, unlit, mesh, box, sphere, cyl, cone, ico, prism, instanced, batch, canvasTexture, group, ground, stage, glow, frame, dots }`

```js
make.stage({ sky: [0x23305e, 0x0d1226], fog: [20, 60] });
make.ground(60, 0x2a3350, { grid: 0x4a5a8a });
const crate = make.box(1, 1, 1, 0xffc145, { at: [0, 0.5, 0] });
```

#### `Kit.make().color(hex)`

Converts an sRGB hex colour to the linear space the renderer works in. Use this for any
THREE.Color you make yourself.

- `hex` *number* - 0xRRGGBB

**Returns** *THREE.Color*

#### `Kit.make().mat(hex = 0xffffff, options = {})`

A lit (standard) material, shared between calls with the same arguments.

- `[hex=0xffffff]` *number* - 0xRRGGBB
- `[options]` *MaterialOptions*

**Returns** *THREE.MeshStandardMaterial*

```js
make.mat(0x66ccff, { emissive: 0x66ccff, emissiveIntensity: 2 })
```

#### `Kit.make().unlit(hex = 0xffffff, options = {})`

A cheap unlit material for backdrops, parallax layers and neon shapes: no lighting cost.

- `[hex=0xffffff]` *number* - 0xRRGGBB
- `[options]` *UnlitOptions*

**Returns** *THREE.MeshBasicMaterial*

#### `Kit.make().instanced(geometry, hexOrMaterial, count, options = {})`

Many copies of one shape in a single draw call, addressed by slot index. Crowds, coins,
scenery, speed lines. (For things that come and go every frame, see make.batch.)

- `geometry` *THREE.BufferGeometry*
- `hexOrMaterial` *number \| THREE.Material*
- `count` *number* - slots; all start hidden
- `[options]` *MaterialOptions & {shadow?: boolean, parent?: THREE.Object3D}* - shadows are OFF unless `shadow: true`

**Returns** *THREE.InstancedMesh* with `place(index, x, y, z, scale = 1, rotationY = 0)`, `placeBox(index, x, y, z, scaleX, scaleY, scaleZ, rotationY = 0)` (stretched per axis, so one unit box can be every tower, plank or speed streak) and `commit()`, which must follow a batch of place calls

```js
const coins = make.instanced(coinGeometry, 0xffc145, 200);
COIN_SPOTS.forEach((spot, index) => coins.place(index, spot.x, 0.5, spot.z));
coins.commit();
```

#### `Kit.make().batch(geometry, capacity, options = {})`

A flat crowd redrawn from plain data every frame: one instanced mesh whose instances are re-listed each frame with their
own position, turn, stretch and HDR colour. Use it when the things are plain objects in an array (enemies, shots,
pickups) that come and go; use make.instanced for a fixed set of slots you move by index.

- `geometry` *THREE.BufferGeometry* - shared shape, e.g. `make.prism(6, 1, 0.1, null, { parent: null }).geometry`
- `capacity` *number* - most instances drawn in one frame
- `[options]` *{ y?: number, material?: THREE.Material, parent?: THREE.Object3D }* - y: height of the plane the instances lie on (default 0); material: defaults to white unlit, so `color` is the colour seen

**Returns** *Batch*

```js
const shots = make.batch(make.box(1, 0.1, 1, null, { parent: null }).geometry, 160, { y: 0.3 });
shots.begin(); bullets.forEach((bullet) => shots.put(bullet.x, bullet.z, bullet.angle, 0.2, 1, SHOT_COLOR, 2.5)); shots.end();
```

#### `Kit.make().canvasTexture(width, height, draw, options = {})`

A texture you paint with canvas 2D.

- `width` *number* - pixels
- `height` *number* - pixels
- `draw` *function(CanvasRenderingContext2D, number, number): void* - called once with (context, width, height)
- `[options]` *Object*
- `[options.repeat]` *[number, number]* - tile it [across, down]
- `[options.pixel]` *boolean* - nearest-neighbour filtering, for crisp pixel art
- `[options.anisotropy]` *number* - e.g. 8 keeps a ground texture sharp at a grazing angle (roads, floors running to the horizon)

**Returns** *THREE.CanvasTexture*

```js
make.canvasTexture(256, 256, (context, width, height) => { context.fillRect(0, 0, width / 2, height / 2); }, { repeat: [4, 4], pixel: true })
```

#### `Kit.make().mesh(geometry, hexOrMaterial, options = {})`

Builds a mesh from any geometry; the base of every shape helper.

- `geometry` *THREE.BufferGeometry*
- `hexOrMaterial` *number \| THREE.Material*
- `[options]` *MeshOptions*

**Returns** *THREE.Mesh* casting and receiving shadows unless `shadow: false`

#### `Kit.make().box(width, height, depth, hexOrMaterial, options)`

Box of width x height x depth (world units).

**Returns** *THREE.Mesh*

#### `Kit.make().sphere(radius, hexOrMaterial, options)`

Sphere of a radius.

**Returns** *THREE.Mesh*

#### `Kit.make().cyl(radiusTop, radiusBottom, height, hexOrMaterial, options = {})`

Cylinder (or cone frustum) with top and bottom radii; `options.seg` sets the radial segments.

**Returns** *THREE.Mesh*

#### `Kit.make().cone(radius, height, hexOrMaterial, options = {})`

Cone; `options.seg` sets the radial segments.

**Returns** *THREE.Mesh*

#### `Kit.make().ico(radius, detail, hexOrMaterial, options = {})`

Low-poly rock / gem: an icosahedron (detail 0 = 20 faces), flat-shaded unless overridden.

**Returns** *THREE.Mesh*

#### `Kit.make().prism(sides, radius, height, hexOrMaterial, options = {})`

Flat n-sided shape lying in the ground plane (triangle, diamond, hexagon ...) for top-down 2D looks.

**Returns** *THREE.Mesh*

#### `Kit.make().group(options = {})`

An empty group, for moving several meshes as one.

- `[options]` *{at?: number[], parent?: THREE.Object3D}*

**Returns** *THREE.Group*

#### `Kit.make().ground(size = DEFAULT_GROUND_SIZE, hexOrMaterial = DEFAULT_GROUND_COLOR, options = {})`

A flat ground plane at y = 0 that receives shadows.

- `[size=60]` *number* - side length, world units
- `[hexOrMaterial=0x2a3350]` *number \| THREE.Material*
- `[options]` *MeshOptions & {grid?: number, cells?: number, gridOpacity?: number}* - `grid`: overlay a subtle grid of this colour; `cells`: grid divisions (default one per 2 units); `gridOpacity` (default 0.25)

**Returns** *THREE.Mesh*

#### `Kit.make().stage(options = {})`

One call for the sky gradient, fog, a hemisphere light and a shadow-casting sun.

- `[options]` *StageOptions*

**Returns** *{sun: THREE.DirectionalLight, hemi: THREE.HemisphereLight, follow: function({x: number, y: number, z: number}): void, setSky: function(number, number, number=): void}* `follow(point)` keeps shadows centred on a moving focus (call it each frame or when the focus moves); `setSky(top, bottom, fogColor = bottom)` repaints the sky at any time, e.g. when blending between altitude zones

```js
const stage = make.stage({ sky: [0x86c5ff, 0xe8f4ff], fog: [30, 90], sun: [-6, 12, 7] });
stage.follow(player.position);
```

#### `Kit.make().glow(hex = 0xffffff, size = 1, options = {})`

An additive soft glow sprite: a cheap halo for pickups, projectiles and lamps. It is
depth-tested by default, so one at floor level is cut by the floor: lift it or pass `depthTest: false`.

- `[hex=0xffffff]` *number* - 0xRRGGBB
- `[size=1]` *number* - diameter, world units
- `[options]` *{opacity?: number, depthTest?: boolean, at?: number[], parent?: (THREE.Object3D\|null)}* - opacity default 0.9

**Returns** *THREE.Sprite*

#### `Kit.make().frame(hex = 0xffffff, options = {})`

A flat square outline lying in the ground plane, 1 x 1 on the outside: scale x / z to fit any footprint.
Landing markers, selection boxes, tile highlights; fx.frame animates one as a pulse.

- `[hex]` *number* - 0xRRGGBB
- `[options]` *{ thickness?: number, bright?: number, opacity?: number, at?: number[], parent?: THREE.Object3D \| null }* - thickness: border width as a fraction of the side (default 0.06); bright > 1 blooms; opacity 0..1; at / parent as for mesh()

**Returns** *THREE.Mesh* unlit and double-sided with its own material, so it is safe to recolour or fade

```js
const marker = make.frame(0xffd27a, { bright: 1.6, at: [0, 0.02, 0] });
marker.scale.set(4, 1, 4);
```

#### `Kit.make().dots(count, options = {})`

A field of screen-sized points that can scroll along y for ever: two copies stacked one `height` apart, wrapped with Kit.span.wrap.
Stars, snow, dust motes, speed streaks. Keep the visible window no taller than `height`.

- `count` *number* - points per copy
- `[options]` *{ width?: number, height?: number, depth?: number[], color?: number, size?: number, bright?: number, parent?: THREE.Object3D }* - width / height: extent of one copy in the parent's units; depth: [near, far] distance behind the parent's origin (-z); color: 0xRRGGBB; size: point size in pixels; bright > 1 blooms

**Returns** *{ group: THREE.Group, material: THREE.PointsMaterial, scroll(offset: number): void, fade(weight: number): void }* scroll: shift the field up by `offset` units (any value, it wraps); fade: 0..1 opacity, hidden near 0

```js
const stars = make.dots(170, { depth: [46, 70], size: 2.2, bright: 1.8, parent: skyGroup });
stars.scroll(-altitude * 0.25); stars.fade(look.stars);
```

### Types

- **MaterialOptions**
  - `[rough=0.6]` *number* - roughness 0 (mirror) .. 1 (matt)
  - `[metal=0]` *number* - metalness 0..1
  - `[emissive=0x000000]` *number* - self-lit colour, 0xRRGGBB
  - `[emissiveIntensity=1]` *number* - above 1 the emissive colour blooms
  - `[opacity=1]` *number* - below 1 the material becomes transparent
  - `[flat=false]` *boolean* - faceted (flat-shaded) look
  - `[fresh=false]` *boolean* - make an uncached copy, for a material you will change per object
- **UnlitOptions**
  - `[opacity=1]` *number*
  - `[additive=false]` *boolean* - add to what is behind (light beams, neon)
  - `[bright=1]` *number* - above 1 pushes the colour past the bloom threshold so it glows
  - `[fresh=false]` *boolean* - make an uncached copy
- **MeshOptions** - Options every shape helper takes: the material options (used when the colour argument is a hex), `at: [x, y, z]`, `parent` (default: the scene; null = do not add anywhere), `shadow: false` to neither cast nor receive, and `seg` for the radial segments of cyl / cone.
- **StageOptions**
  - `[sky]` *[number, number]* - [top, bottom] gradient colours, 0xRRGGBB
  - `[fog]` *[number, number]* - [near, far] distances in world units; omitted = no fog
  - `[fogColor]` *number* - defaults to the sky's bottom colour, so the horizon blends
  - `[sun]` *[number, number, number]* - sun position relative to the focus point
  - `[sunColor]` *number*
  - `[sunIntensity=1.25]` *number*
  - `[skyLight]` *number* - hemisphere light colour from above
  - `[groundLight]` *number* - hemisphere light colour from below
  - `[ambient=0.7]` *number* - hemisphere light intensity
  - `[shadow=16]` *number* - half-width of the shadowed area round the focus, world units
- **Batch**
  - `mesh` *THREE.InstancedMesh* - the one mesh (and draw call) behind every instance
  - `begin` *function(): void* - start a frame: forget last frame's instances
  - `put` *function(number, number, number, number, number, THREE.Color, number=): void* - put(x, z, rotationY, scaleX, scaleZ, color, bright = 1): add one instance on the batch's plane; `color` is a linear THREE.Color (make.color) and is not kept; bright > 1 blooms. Calls past the capacity are dropped.
  - `end` *function(): void* - finish the frame: show exactly what was put since begin()

## theme.js

> Kit theme: the customisation layer that lets each game's HUD look native to that game.
>
> Owns: design tokens (CSS custom properties), skins (named starting points), font loading, per-game scoped CSS,
>       and applying / clearing all of that when a game starts or exits.
> Does not own: the HUD components themselves (kit/ui.js builds them and consults `theme.components` for overrides)
>       or the base stylesheet (index.html, which reads every token listed in TOKEN_DEFAULTS).
>
> A game opts in from its registration:
>
>   Kit.register({
>     id: 'cozy',
>     theme: {
>       skin: 'paper',                                   // start from a skin (see SKINS)...
>       fonts: ['Pixelify Sans:wght@500;700'],           // ...load Google Fonts families...
>       tokens: { '--display': '"Pixelify Sans", monospace', '--accent': '#e2725b' },   // ...override tokens...
>       layout: { stats: 'top-center', actions: 'bottom' },                            // ...place the HUD regions...
>       css: '& .stat { transform: rotate(-1.5deg); }',  // ...add CSS scoped to this game ("&" is the game's root)...
>       components: { stat: ({ label, value, h }) => customElement },                  // ...or rebuild a component.
>     },
>     create(ctx) { ... },
>   });
>
> Everything is optional: a game with no `theme` gets the default "glass" skin.

### `Kit.theme.SKINS`

Skins: complete looks a game can start from. Each is just a Theme, so a game's own theme merges over it.
Add a skin by adding a row; nothing else needs to change.

### `Kit.theme.TOKEN_DEFAULTS`

Every token the base stylesheet reads, with the value used when neither the skin nor the game sets it.
Colours are any CSS colour; sizes are CSS lengths.

### `Kit.theme.resolve(gameTheme = {})`

Merge a game's theme over its skin. Tokens and components merge key by key; fonts concatenate; css concatenates.

- `[gameTheme]` *Theme*

**Returns** *Required\<Theme\>* A complete theme with every field present.

### `Kit.theme.apply(gameId, gameTheme)`

Apply a game's theme to the page: tokens on <body>, skin / game / layout as data attributes for CSS to key on,
fonts requested, scoped CSS installed. Returns the resolved theme so kit/ui.js can read `components`.

- `gameId` *string* - The game's registered id; scoped CSS only matches while this game is active.
- `[gameTheme]` *Theme*

**Returns** *Required\<Theme\>*

### `Kit.theme.clear()`

Remove every trace of the active theme (called when a game exits to the menu or restarts).

### `Kit.theme.loadFonts(families)`

Ask the browser to load Google Fonts families that have not been requested yet.
Google Fonts is the only font host the published page's security policy allows.

- `families` *string[]* - css2-form family specs, e.g. 'Fredoka:wght@500;700'.

### Types

- **Theme**
  - `[skin]` *string* - Name of a skin in SKINS to start from. Default 'glass'.
  - `[fonts]` *string[]* - Google Fonts families in css2 form, e.g. 'Pixelify Sans:wght@500;700'.
  - `[tokens]` *Record\<string, string\>* - Token overrides; keys are the names in TOKEN_DEFAULTS (or your own).
  - `[layout]` *{ stats?: 'top-right'\|'top-center'\|'top-left', actions?: 'bottom'\|'bottom-right' }*
  - `[css]` *string* - Extra CSS. "&" is replaced by a selector matching only this game's HUD.
  - `[components]` *Record\<string, Function\>* - Component builders that replace the kit's (see kit/ui.js).

## ui.js

> Kit ui: the HUD, built from a few primitives.
>
> Owns:  HUD widgets (stat, pips, progress, actions, toast, hint, el), modals that pause the game
>        (choose, banner, panel) and the adapters that draw a Kit model (shop and offer for
>        Kit.upgrades, checklist for Kit.goals). Everything it adds is removed by `dispose()`,
>        which the shell calls when the game exits or restarts.
> Does not own: how the HUD looks (the base stylesheet in index.html and the game's theme, see
>        theme.js; a theme may also rebuild a component through `theme.components`), the models
>        themselves (model.js) or canvas input (input.js).
>
> Needs the DOM, so it is exercised by tools/smoke.js rather than unit tests.

### `Kit.ui(ctx)`

Creates the HUD for a game. The shell does this and exposes it as `ctx.ui`.


## views.js

> Kit views: build-crafting screens generated from kit models. Model in, element out; each view re-renders itself when
> its model changes. Put the element anywhere (usually inside ui.panel) and call dispose() when it is closed.
>
>   tree      - skill tree from a Kit.upgrades model whose rows carry `row` / `col` / `requires`   Kit.views.tree(upgrades, { wallet })
>   inventory - bag and equipment from Kit.inventory + Kit.loot, with compare, equip and salvage    Kit.views.inventory(inventory, { loot })
>   roll      - slot-style reel over a weighted table that stops on a winner chosen beforehand      Kit.views.roll({ entries, winner })
>   progressList - any list of titled entries with a counter and a progress bar                     Kit.views.progressList(readEntries, models)
>   deeds     - achievements of a Kit.profile with live progress                                    Kit.views.deeds(profile)
>   synergies - set bonuses of a Kit.synergy with the tags still missing                            Kit.views.synergies(synergy)
>
> Owns: the markup, the default look and the taps of those screens.
> Does not own: the decisions they show (kit/craft.js, unit-tested), the models (kit/model.js, kit/loot.js), or the
>               modal they sit in (ui.panel).
>
> Theming: every colour, font and radius comes from the theme tokens (kit/theme.js) or from the view tokens in
> VIEW_TOKEN_DEFAULTS below, so a game restyles a view from `theme.tokens` and `theme.css` alone. The class names are a
> stable contract for scoped CSS:
>   .kv-tree  .kv-tree-heads  .kv-tree-lines line[data-active]  .kv-node[data-status][data-owned]  .kv-node-mark
>   .kv-inventory  .kv-slot  .kv-item (its rarity colour is the CSS variable --c)  .kv-compare .is-better / .is-worse
>   .kv-roll  .kv-reel  .kv-reel-row (colour --c)  .kv-roll[data-landed]  .kv-roll-result
>   .kv-list  .kv-entry[data-done]  .kv-entry-bar (its fill is the CSS variable --progress, 0..1)

### `Kit.views.VIEW_TOKEN_DEFAULTS`

Tokens only the views read. A game overrides them like any theme token (`theme.tokens`).

### `Kit.views.tree(upgrades, options = {})`

Skill tree generated from a Kit.upgrades model. Rows are placed by their `row` (tier, 0 at the top) and `col`
fields, lines join each node to its `requires`, and a tap buys. Every node shows its name, what the next level
does and its price; its `data-status` (see Kit.craft.nodeStatus) drives the locked / available / owned looks.

- `upgrades` *Object* - a Kit.upgrades model (rows need integer `row` and `col`)
- `[options]` *Object*
- `[options.wallet]` *Object* - the Kit.wallet the tree spends from; shows the balance and re-renders on change
- `[options.currency]` *string* - which wallet currency to show (default: the wallet's default)
- `[options.pointsLabel]` *string* - text before the balance (default 'Points')
- `[options.heads]` *string[]* - a title per column (branch names)
- `[options.anchor]` *{ x: number, y: number }* - where lines attach in a cell, 0..1 (default the centre); move it when your CSS draws a node's mark (.kv-node-mark) away from the centre
- `[options.onBuy]` *(row: Object, level: number) =\> void* - called after a successful purchase

**Returns** *{ element: HTMLElement, refresh: () =\> void, dispose: () =\> void }*

**Complexity** render: O(rows + edges) elements, rebuilt on every model change (a tree is a few dozen nodes).

```js
const view = Kit.views.tree(tree, { wallet, currency: 'souls', heads: ['Reaper', 'Warden', 'Occult'] });
ui.panel({ title: 'Soul Tree', build: (body) => body.append(view.element) }).then(view.dispose);
```

### `Kit.views.inventory(inventoryModel, options)`

Inventory generated from a Kit.inventory and the Kit.loot that rolled its items: the worn item per slot, then every
bag item as a card in its rarity colour with its describe lines, a compare against what is worn, and Equip /
Salvage buttons.

- `inventory` *Object* - a Kit.inventory
- `options` *Object*
- `options.loot` *Object* - the Kit.loot generator (for describe)
- `[options.labels]` *Record\<string, string\>* - stat name -> display name, for describe and compare lines
- `[options.compareStats]` *string[]* - stats to compare (default: none, which hides the compare line)
- `[options.percent]` *string[]* - see Kit.craft.compareLines
- `[options.lowerIsBetter]` *string[]* - see Kit.craft.compareLines
- `[options.slotLabels]` *Record\<string, string\>* - slot id -> display name
- `[options.tag]` *(item: Object) =\> string* - small text beside an item's name (rarity, level, "Cursed")
- `[options.decorate]` *(card: HTMLElement, item: Object) =\> void* - last word on each bag card: add data attributes or badges your scoped CSS keys on (for example card.dataset.cursed)
- `[options.onEquip]` *(item: Object) =\> void* - called after an item is equipped
- `[options.salvage]` *{ label: (item: Object) =\> string, onSalvage: (item: Object) =\> void }* - adds a Salvage button; the view removes the item from the bag, then calls onSalvage(item) for the payout

**Returns** *{ element: HTMLElement, refresh: () =\> void, dispose: () =\> void }*

**Complexity** render: O(items x compareStats), rebuilt on every inventory change (a bag is a few dozen items).

```js
const view = Kit.views.inventory(inventory, { loot, labels: STAT_LABELS, compareStats: ['damage', 'maxHp'],
  salvage: { label: (item) => `Salvage +${soulsFor(item)}`, onSalvage: (item) => wallet.add(soulsFor(item), 'souls') } });
```

### `Kit.views.roll(options)`

Slot-style roll: a reel of weighted entries spins and stops on `winner`, then a result line and a "take" button
appear. The outcome is decided by the caller before the view is made; the view only reveals it. Declining is the
host's job (for example the close button of ui.panel), so the caller can word and price it.

- `options` *Object*
- `options.entries` *RollEntry[]* - the weighted table the reel shows
- `options.winner` *RollEntry* - the entry to stop on (one of `entries`)
- `[options.describe]` *(entry: RollEntry) =\> string* - result text once landed
- `[options.takeLabel]` *(entry: RollEntry) =\> string* - text of the take button (default 'Take')
- `[options.onLand]` *(entry: RollEntry) =\> void* - called when the reel stops
- `options.onTake` *(entry: RollEntry) =\> void* - called when the take button is pressed
- `[options.spinMs]` *number* - spin duration in milliseconds
- `[options.rng]` *Object* - a Kit.rng for the filler rows

**Returns** *{ element: HTMLElement, dispose: () =\> void }* dispose cancels a spin still in progress

**Complexity** O(strip length) elements once (about 27 rows); the spin itself is one CSS transition.

```js
ui.panel({ title: 'Absorb', closeLabel: 'Bank it: +3 souls', build: (body, close) =>
  body.append(Kit.views.roll({ entries: pool, winner, onTake: () => close('take') }).element) });
```

## post.js

> Kit post: the post-processing chain. HDR render -> bloom -> one final pass that applies
> exposure, vignette, ACES tone mapping and sRGB output.
>
> Owns:  building that chain, its per-scene tuning (`ctx.post.bloom`, `ctx.post.vignette`,
>        `ctx.post.exposure`) and switching it off and on.

>        the device is too slow for it (the shell's quality governor calls `disable`), or what

> Where HDR render targets or the three.js post-processing addons are missing, every method is a
> no-op and `render` draws the scene directly, so callers never need to check.
> Needs WebGL, so it is exercised by tools/smoke.js rather than unit tests.

## ballistics.js

> Kit ballistics: the maths of thrown things. Pure: plain { x, y, z } objects in, plain data out; no DOM, THREE or cannon
> (unit-tested in tools/test-kit.js).
>
>   direction   - unit aim vector from a yaw and a loft angle:    Kit.ballistics.direction(0.2, 0.5)
>   trace       - the flight path a physics body will follow:     Kit.ballistics.trace({ origin, velocity, acceleration, stopWhen })
>   sphereTouchesBox - cheap obstacle test for a trace:           Kit.ballistics.sphereTouchesBox(point, radius, box)
>   blastKick   - velocity change an explosion gives a point:     Kit.ballistics.blastKick(centre, point, { radius, kick, lift })
>
> Owns: aim geometry, trajectory prediction and explosion falloff. Does not own: bodies, collisions or rendering
> (Kit.physics applies blastKick to cannon bodies; the game decides how to draw a trace).

### `Kit.ballistics.direction(yaw, loft)`

Unit vector for an aim given as two angles. Yaw 0 looks down -z (away from a camera on +z), like the kit's stages.

- `yaw` *number* - Radians around the vertical axis; positive turns toward +x.
- `loft` *number* - Radians above the horizon.

**Returns** *Vector* Unit direction.

### `Kit.ballistics.advance({ position, velocity }, acceleration, step)`

One semi-implicit Euler step (velocity first, then position): the integrator cannon.js and most game physics use, so
a trace built from it lands exactly where an undamped body will.

- `state` *{ position: Vector, velocity: Vector }*
- `acceleration` *Vector* - Units per second squared (gravity plus any wind).
- `step` *number* - Seconds.

**Returns** *{ position: Vector, velocity: Vector }* The next state (a new object).

### `Kit.ballistics.trace({ origin, velocity, acceleration = { x: 0, y: -20, z: 0 }, step = 1 / 60, maxSteps = 120, stopWhen = () => false })`

Predicts a flight path by stepping the launch state until `stopWhen` says the point has hit something.

- `options` *object*
- `options.origin` *Vector* - Launch point.
- `options.velocity` *Vector* - Launch velocity, units per second.
- `[options.acceleration]` *Vector* - Constant acceleration; defaults to gravity of -20 on y (the Kit.physics default).
- `[options.step]` *number* - Seconds per step; match the physics step (1/60) for an exact preview.
- `[options.maxSteps]` *number* - Upper bound on steps, so a shot into the sky still ends.
- `[options.stopWhen]` *(point: Vector, index: number) =\> boolean* - True when the point is inside an obstacle.

**Returns** *{ points: Vector[], end: Vector, isBlocked: boolean }* `points` are the free-flight positions after each step, `end` is the blocked point (or the last free one when nothing was hit), `isBlocked` says which.

```js
const flight = Kit.ballistics.trace({ origin, velocity, stopWhen: (point) => point.y < ballRadius });
flight.points.filter((_, index) => index % 3 === 0).forEach(placeDot);
```

### `Kit.ballistics.sphereTouchesBox(point, radius, box)`

Whether a sphere overlaps an axis-aligned box, tested as "centre inside the box grown by the radius". That rounds the
box corners outward slightly, which is the right bias for a preview: it never draws a path through a corner.

- `point` *Vector* - Sphere centre.
- `radius` *number* - Sphere radius.
- `box` *Box*

**Returns** *boolean*

### `Kit.ballistics.blastKick(centre, point, { radius, kick, lift = 0 })`

Velocity change an explosion gives something at `point`: pushed straight away from the centre, strongest at the centre
and fading linearly to nothing at `radius`, plus an optional upward share so debris arcs instead of sliding.

- `centre` *Vector* - Where the blast is.
- `point` *Vector* - Where the affected thing is.
- `blast` *object*
- `blast.radius` *number* - Reach in world units; at or beyond it nothing happens.
- `blast.kick` *number* - Speed change at the centre, units per second.
- `[blast.lift]` *number* - Extra upward speed as a fraction of the falloff-scaled kick (0.3 = 30%).

**Returns** *Vector \| null* The velocity to add, or null when the point is out of reach.

### Types

- **Box** - A point, velocity or acceleration in world units (metres, seconds).

## loadout.js

> Kit loadout: a fixed row of slots filled from a collection under a point budget.
>
> Owns:  which id sits in which slot, what the picks cost in total and whether a swap still fits the budget.
> Does not own: the collection (pass the ids you offer), what an id means, or any view (the game draws the slots).
> Pure: no DOM, no THREE; unit-tested in tools/test-kit.js.
>
> This is the "decision with a trade-off" model: three shots and five points buy one bomb and two plain balls, or two
> splitters and nothing else. The same shape fits ability bars, squad pickers and deck slots.

### `Kit.loadout({ slots, budget, costOf, initial = [] })`

Create a loadout.

**Complexity** every call is O(slots); `cycle` is O(slots x ids). Memory: O(slots).

```js
const loadout = Kit.loadout({ slots: 3, budget: 5, costOf: (id) => BALLS.byId(id).cost, initial: ['heavy', 'heavy', 'heavy'] });
```

## physics.js

> Kit physics: a thin wrapper over cannon.js (global CANNON).
>
> Owns:  one physics world with sensible defaults (fixed 60 Hz timestep, sleeping on), rigid
>        bodies paired with the meshes that show them, mesh <- body syncing after each step,
>        impact callbacks, static scenery, bounds, pushes and blasts.
> Does not own: the meshes themselves (make.js), projectile and blast maths as plain data
>        (ballistics.js) or the frame loop: the game calls `phys.step(dt)` from its update.

> Needs cannon.js, so it is exercised by tools/smoke.js rather than unit tests.

- `nameA` *string*

## bodies.js

> Kit bodies: the pieces Kit.physics (kit/physics.js) needs for built contraptions and 2D-in-3D games. Each helper takes

## touch.js

> Kit touch: the pure models behind finger-skill moments. No DOM, no THREE - runs in node (see tools/test-kit.js).
>
>   trace  - follow a moving Kit.path target: catch meter, line tension, streak, accuracy   trace.step(state, dt, pointer)

### `Kit.touch.trace(options)`

### `Kit.touch.lasso(points, targets, { closeTolerance = Infinity, at = (target) => target } = {})`

## pixel.js

> Kit pixel: pixel-paper sprites. Pixel art is written as data (rows of characters + a palette, optionally several frames),
> baked into a crisp nearest-filtered texture with an off-white paper border, and stood up in the scene as a paper cut-out.
>
>   const ART = Kit.pixel.sheet(PALETTE, { hero: { frames: [[...rows], [...rows]], anims: { walk: [1, 0] } }, tree: [...rows] });
>   const paper = Kit.pixel.use(ctx, { unit: 1 / 16, lean: 0.3, shadow: true, tint });      // per-game defaults
>   const hero = paper.sprite(ART.hero, { at: [x, y, z] });
>   hero.play('walk', 9);  hero.face(-1);  hero.hop(0.3);  hero.squash();   // frames, paper flip, springy feedback
>   paper.update(dt);                                                       // once per frame, drives every sprite
>
> Owns: sprite definitions as data (sheet / recolor / tile / label / cells), baking them to textures, the paper sprite
> with its frame, flip, hop and squash animation, and true-colour unlit materials (paper.flat) for backdrops and water.
> Does not own: movement, game rules or the art itself.
>
> Colour: sprites are unlit and sRGB-correct. While the kit's post pass is on they pre-invert its ACES curve, so palette
> colours reach the screen as written; paper whites then sit near 2.3 in HDR, so use ctx.post.bloom(0), or a bloom
> threshold of 2.5 or more, to keep them matte.

### `Kit.pixel.use(ctx, defaults = {})`

- `ctx` *Object* - The game ctx (scene, post).
- `[defaults]` *SpriteOptions* - Defaults for every sprite: { unit: 1 / 16, lean: 0, shadow: true, tint: white }.

**Returns** *{ sprite: (def: SpriteDef, options?: SpriteOptions) =\> PaperSprite, flat: (map?: Object \| null, options?: Object) =\> Object, tint: Object, update: (dt: number) =\> void }*

**Complexity** update: O(s) per frame for s visible sprites, with no allocation. Sprites of one definition share a texture and a material, so draw state changes scale with definitions, not sprites.

#### `Kit.pixel.use().sprite(def, options = {})`

- `[options]` *SpriteOptions*

**Returns** *PaperSprite*

#### `Kit.pixel.use().flat(map = null, { color = 0xffffff, opacity = 1, additive = false, alphaTest = 0 } = {})`

An unlit, double-sided material with the same true-colour handling as the sprites (backdrops, water, rings).

- `[map]` *Object \| null* - THREE.Texture or null for a plain colour.
- `[options]` *{ color?: number \| Object, opacity?: number, additive?: boolean, alphaTest?: number }* - color: 0xRRGGBB, or a THREE.Color instance that stays shared (mutate it to recolour every user).

**Returns** *Object* THREE.MeshBasicMaterial

#### `Kit.pixel.use().update(dt)`

_Undocumented: add a JSDoc block in the source._

### `Kit.pixel.sheet(pal, table)`

Turn a table of art into named definitions that share one palette.

- `pal` *Object\<string, number\>*
- `table` *Object\<string, string[] \| Partial\<SpriteDef\>\>* - name -> rows, or a partial definition.

**Returns** *Object\<string, SpriteDef\>*

**Complexity** O(n) for n entries; the rows themselves are shared, not copied.

### `Kit.pixel.texture(def)`

The baked texture of a definition (cached per definition object).

- `def` *SpriteDef*

**Returns** *Baked*

### `Kit.pixel.canvas(def, { frame = 0, scale = 4 } = {})`

One frame as a plain canvas scaled by whole pixels, for HUD cards and shop icons.

- `def` *SpriteDef*
- `[options]` *{ frame?: number, scale?: number }* - scale: screen pixels per art pixel (default 4).

**Returns** *HTMLCanvasElement*

### `Kit.pixel.cells(def, frame = 0, border = borderOf(def))`

Every pixel to paint for one frame: the art, plus a paper border around its silhouette.

- `def` *SpriteDef*
- `[frame=0]` *number*
- `[border]` *number* - Border width in pixels (default: the definition's own).

**Returns** *Cell[]* Cells may have negative coordinates: the border sits outside the art's box.

**Complexity** O(w x h x b^2) time for a w x h frame with border b (each empty pixel looks at its (2b+1)^2 neighbours), O(w x h) space. Runs once per definition at bake time, never per frame.

```js
Kit.pixel.cells({ rows: ['r'], pal: { r: 0xff0000 } });   // 1 red cell + 8 paper cells around it
```

### `Kit.pixel.label(text, { ink = LABEL_INK, fill = PAPER } = {})`

A paper tag with text in the 3x5 pixel font (capitals, digits and ! ? + - . only; anything else is a space).

- `text` *string*
- `[colors]` *{ ink?: number, fill?: number }* - Text and background colours, 0xRRGGBB.

**Returns** *SpriteDef*

**Complexity** O(characters).

### `Kit.pixel.recolor(def, swaps)`

A copy of a definition with some palette colours swapped (blossom tree from a green tree).

- `def` *SpriteDef*
- `swaps` *Object\<string, number\>* - character -> new 0xRRGGBB.

**Returns** *SpriteDef*

### `Kit.pixel.tile(def, count)`

A single-frame definition made of `count` copies of a sprite's first frame side by side (fence runs, wave strips).

- `def` *SpriteDef*
- `count` *number*

**Returns** *SpriteDef*

**Complexity** O(rows x count) characters.

### `Kit.pixel.PAPER`

Paper colour of the border around every cut-out, and the darker tone used directly under the art (a cut edge).

## dev.js

> Kit dev: what a developer sees that a player never does.
>
> Owns:  `Kit.debug.state()` (one plain snapshot of the running game for tools and the overlay),
>        `Kit.debug.probe()` (frame-time percentiles and render cost), the development-time checks on HUD and
>        helper calls (wrong argument type, a fourth stat, a HUD element pushed off-screen, a raw THREE.Color),
>        and the developer overlay `Kit.dev` (frame time, live state, skin switcher, time scale, last error).
> Does not own: registration checks (Kit.checkGame in core.js), Kit.warn / Kit.expectType themselves (core.js),
>        or the command-line tools that read all this (tools/dev.js, tools/smoke.js).
>
> Cost: in a published page nothing here is installed except the two small `Kit.debug` readers and `Kit.dev`;
> the checks wrap kit factories only when Kit.isDevelopment() is true, and the overlay builds its DOM and starts
> its timers only while it is open. Loaded after the other kit modules and before the games and the shell.

### `Kit.dev`

The developer overlay: frame time, live debug state, a skin switcher, time scale and the last error.
Open it with the backquote key or a three-finger tap (development only), or `Kit.dev.open()` from the
console anywhere. Closed, it has no DOM, no timers and no per-frame work.

```js
Kit.dev.toggle();
```

### `Kit.dev.isOpen()`

Is the overlay showing?

### `Kit.dev.open()`

Shows the overlay and starts its frame meter and refresh timer. Does nothing when it is already open.

### `Kit.dev.close()`

Removes the overlay and stops everything it started.

### `Kit.dev.toggle()`

Opens the overlay when it is closed and closes it when it is open.

### Types

- **DebugState**
  - `id` *?string* - the running game's id ('_attract' on the menu), or null before the shell starts
  - `time` *number* - game seconds since the game started
  - `paused` *boolean*
  - `timeScale` *number*
  - `modal` *?string* - title of the open modal, or null
  - `hud` *Object\<string, (number\|string)\>* - the stats row as label -> value
  - `actions` *string[]* - labels of the enabled bottom-bar buttons
  - `state` *?Object* - what the game's own `debugState()` returned, or null when it has none
  - `crash` *?string* - the last crash message (Kit.lastCrash), or null
- **FrameProbe**
  - `frames` *number* - frames measured
  - `frameMs` *number[]* - frame time at the 50th, 95th and 99th percentile, milliseconds
  - `calls` *number* - most draw calls in one frame
  - `triangles` *number* - most triangles in one frame
  - `meshes` *number* - visible meshes, points, lines and sprites in the scene at the end

## shell.js

> Kit shell: the renderer, the frame loop, the game lifecycle and the menu. Loaded last, after
> every kit file and every game.
>
> Owns:  the one WebGL renderer and its size, building the `ctx` each game receives, launching,
>        restarting and disposing games, the frame loop (game time, pause, hitstop, slow motion),
>        crash recovery back to the menu, the quality governor, the idle backdrop behind the
>        menu, the menu cards and the top-bar buttons (back, restart, mute).
> Does not own: anything a game does with its ctx; the pieces of the ctx themselves (input.js,
>        fx.js, ui.js, make.js, post.js, theme.js, core.js); page markup and styles (index.html).
>
> Public surface: `Kit.play(id)`, `Kit.menu()`, `Kit.current` (the live ctx, for tests and
> tools), `Kit.lastCrash` and `Kit.post_` (test hook).
> Needs the DOM and WebGL, so it is exercised by tools/smoke.js rather than unit tests.

### `Kit.play(id)`

Starts a registered game by id.

- `id` *string*

**Returns** *boolean* false when no game has that id

### `Kit.menu`

Returns to the menu.

### `Kit.post_`

Test hook: tools/smoke.js switches bloom off while playing and on for screenshots.

### Types

- **ViewSize** - The stage size, shared (as one live object) with every game through `ctx.size`.
  - `w` *number* - width, CSS pixels
  - `h` *number* - height, CSS pixels

  - `portrait` *boolean* - is it at least as tall as it is wide?
